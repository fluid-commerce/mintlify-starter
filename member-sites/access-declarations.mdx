A member site's JavaScript reads the signed-in owner's data and acts as the owner through `window.fluid`. Each call needs a scope, such as `profile: read`. A site says which scopes its scripts use in one file, `config/access.json`. Lint checks your scripts against it, and Fluid publishes it with the site.

This page lists every scope a site can declare. It also covers how to write the file, how to check it before you publish and where the published declaration is reported. To see the calls themselves, read [Read viewer data in site scripts](/member-sites/site-scripts).

<Note>
  Member sites must be turned on for your company by Fluid. To ask for them, [contact support](/help/getting-help). This page is about the [member sites](/member-sites/overview) that members and companies build, not the pages a theme's [member storefront](/themes/member-storefront/member-sites) groups into sites.
</Note>

## Know how a declaration works

- **A declaration lists what the site's scripts use.** Each entry is a scope, such as `tasks: write`. Declare the scope of every `window.fluid` call your scripts make, and nothing else.
- **Lint checks your scripts against it.** `fluid member-site lint` warns on a script call whose scope the file lacks. A site with no file isn't checked this way.
- **A declaration is a draft until you publish.** Fluid publishes the declaration together with the site's settings. A site's `access` field reports the declaration the site last published, never the draft.
- **Only member-owned sites have one.** A company site takes no declaration. The file API refuses `config/access.json` on a company site, and a company site never lists it.
- **A declaration gives nobody data they wouldn't have had.** Only the signed-in owner of a member-owned site gets data from the site's scripts. See [Know who gets data](/member-sites/site-scripts#know-who-gets-data).

## Write a declaration

`config/access.json` is one JSON object with one key, `uses`. It holds a list of scope strings.

```json config/access.json
{
  "uses": [
    "profile: read",
    "tasks: read",
    "tasks: write"
  ]
}
```

This declaration fits a site whose scripts read the member with `fluid.me.get()`, list tasks with `fluid.tasks.list()`, and complete or reopen them:

```js
const me = await fluid.me.get();
const tasks = await fluid.tasks.list();
await fluid.tasks.complete(tasks[0].id);
```

- A **scope** is `<family>: read` or `<family>: write`, such as `tasks: read`. `write` doesn't include `read`, so a site that does both declares both.
- The file is at most 4 KiB and lists at most 64 entries, with no entry twice.
- Fluid refuses a file with an unknown key, a repeated key, an entry that isn't a string, an unknown field, family or mode, or `session: read`.
- Don't declare `session: read`. Lint reports it as an error.
- `{ "uses": [] }` is a site whose scripts make no `window.fluid` call. With no file, lint doesn't check calls. With an empty list, lint warns on every call.
- A file written earlier may still list entries such as `member.email`. Fluid accepts them so that file stays valid, but your scripts don't need them. To read the member in a script, declare `profile: read` and call `fluid.me.get()`.

## Declare scopes

A scope names a family of the member API and a mode. These are the families a site can declare.

| Family | What it covers |
| --- | --- |
| `addresses` | The member's saved addresses |
| `agreements` | The agreements that apply to the member and their acceptance |
| `ai` | Conversations with the assistant, their messages and feedback |
| `calendar` | Calendar events and catch-ups |
| `carts` | The member's carts |
| `contacts` | Contacts and their notes and tasks, contact imports, groups and notes |
| `media` | Media, direct uploads, playlists and their items |
| `messages` | Conversations and messages, and sending a message from a native widget |
| `mysite` | MySite settings, themes, links and statistics |
| `notifications` | Notification preferences, push devices and the activity feed |
| `orders` | The member's orders |
| `plan` | The member's Pro plan, the plans on offer and paid add-ons |
| `points` | The points balance and ledger |
| `profile` | The signed-in member and their profile and social links |
| `search` | Catalog search |
| `shares` | Tracked shares, referral shares and photo shares, including from a native widget |
| `stats` | Dashboard totals and top assets |
| `subscriptions` | The member's subscriptions, their bundles, discounts and waivers, and a native widget's subscription summary |
| `tasks` | The member's tasks, including completing and reopening one from a native widget |
| `widgets` | The member storefront's native widget routes for data, schedules, sales goals and earnings goals |

Use `read` for calls that read and `write` for calls that change something.

### Match the SDK calls

Each named `window.fluid` call needs one scope:

| Call | Scope |
| --- | --- |
| `fluid.me.get()` | `profile: read` |
| `fluid.me.update(fields)` | `profile: write` |
| `fluid.tasks.list()` | `tasks: read` |
| `fluid.tasks.complete(id)` and `fluid.tasks.reopen(id)` | `tasks: write` |
| `fluid.team.list({ under })` | `widgets: read` |

`fluid.team.list` needs `widgets: read`, not a `team` scope, because the team tree comes from a native widget route. Lint doesn't know which scope a `fluid.fetch` call needs, so it doesn't check one.

## Publish, change and remove a declaration

Write the file with the file API, or with the CLI by editing the pulled folder and pushing it. A declaration you write is a draft until the site publishes.

- **Publish.** Publishing the site publishes the declaration together with the settings.
- **Change.** Edit the file, push it and publish again.
- **Remove.** Delete `config/access.json` and push. That clears the draft declaration only: the published one stays until you publish the site. Publishing a site with no draft declaration removes the one it had published.
- **Copy.** A member's copy of a member's site starts with the original's published declaration as its own draft. A company admin's copy of a member's site starts with none, because a company site takes no declaration. After that, changes to either site never change the other.
- **Company sites.** The file API refuses the path on a company site, and `fluid member-site push` leaves it alone.

See [Write a site file](/api-reference/site-files/write-a-site-file) and [Publish a site](/api-reference/sites/publish-a-site) for the API, and the [CLI page](/member-sites/cli) for `pull`, `push` and `publish`.

## Check a declaration

The CLI carries the file with the other site files:

- **`pull` writes it.** `pull` writes `config/access.json` into the folder when the site has a draft declaration. When the site no longer has one, `pull` deletes your local copy if you haven't edited it since the last pull or push. A copy you edited stays, unless you pull with `--force`.
- **`push` sends it.** `push` sends the file with the other site files, and a push with no edit sends nothing for it. `push` refuses an invalid declaration before it sends any request.

Run `fluid member-site lint` in the folder before you push. It sends no request.

- **An invalid file is an error.** Lint reports each problem the file API would refuse: not valid JSON, a key other than `uses` or a repeated key, an entry that isn't a string or appears twice, an unknown field, family or mode, `session: read`, more than 64 entries, and a file over 4 KiB.
- **A script call the declaration lacks is a warning.** When the file is valid, lint warns for each `window.fluid` call a script makes whose scope the declaration doesn't list, such as `fluid.me.update(` without `profile: write`.
- **A Liquid file that reads `member.<field>` is a warning.** Lint warns whatever the declaration holds, because member data is leaving member site Liquid. Read it in a script with `fluid.me.get()`, which needs `profile: read`.

A warning doesn't fail the command.

## See what a site declares

The site's payload in the member API and the company API carries the published declaration as `access`, with `declared` and the list of `uses`. `declared` is `false` for a site that has published no declaration, and for a company site. Menu entries in the member's account menu carry it too.

The summary describes a declaration. It doesn't change who gets data. See [Show a site](/api-reference/sites/show-a-site) and [Get a member site](/api-reference/member-sites/get-a-member-site).

## Fix a declaration

| You see | Why | What to do |
| --- | --- | --- |
| Lint warns about a call, such as `fluid.me.update(` | The script makes a call whose scope the file lacks | Add the scope, such as `profile: write`, or remove the call |
| Lint reports `session: read` as an error | The file lists a scope you never declare | Remove the entry |
| Lint warns about `member.<field>` in a Liquid file | Viewer data is leaving member site Liquid | Read it in your script with `fluid.me.get()` and declare `profile: read` |
| A share holder or visitor gets no data | Only the owner gets data from the site's scripts | This is by design. Sharing grants nothing |
| The CLI skips `config/access.json` | The site is a company site | Company sites take no declaration |
| The site's `access` doesn't show your edit | The declaration is still a draft | Publish the site |
