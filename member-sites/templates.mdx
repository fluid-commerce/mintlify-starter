A member site is its own small theme. Its pages are Liquid templates that read only the site's own files. This page covers what a site holds, the Liquid objects its templates can read, and the rules of the frame it renders in. To read a member's data, use a script instead: see [Read viewer data in site scripts](/member-sites/site-scripts).

<Note>
  Member sites are not storefront themes. A site can't use a theme's files, settings or stylesheets, and `fluid theme` commands don't touch it. See the [overview](/member-sites/overview).
</Note>

## Know the folder

A site holds six kinds of file. In the [CLI](/member-sites/cli), each lives in a folder of the same name, and a path in the folder is the path the file API uses.

| Folder | What it holds |
| --- | --- |
| `layouts/` | The templates that frame a page, such as `layouts/site.liquid` |
| `sections/` | Reusable blocks of a page, such as `sections/hero.liquid` |
| `snippets/` | Small shared fragments, such as `snippets/card.liquid` |
| `pages/` | One template for each page. `pages/about.liquid` is a page's content, and `pages/index.liquid` is the home page |
| `assets/` | Text assets: CSS, JavaScript, JSON, text and HTML files |
| `config/` | `settings.json`, `menus.json`, `pages.json` and `access.json` |

- **No subfolders.** A name uses lowercase letters, digits, hyphens and underscores. Names that start with a dot are ignored.
- **A page is a file and a row.** `pages/<slug>.liquid` holds the content, and a row in `config/pages.json` holds the slug, title, position, published flag, layout and menu. A new page needs both. A site holds at most 50 pages.
- **The home page's slug is `/`** in `config/pages.json`, and its file is `pages/index.liquid`. A slug is never `index`.

The [CLI page](/member-sites/cli#know-the-folder) shows the folder, and [Pages and menus](/member-sites/pages-and-menus) explains the config files.

## Pick a layout

A page uses its row's `layout`, else the site's default `layout`, else `layouts/site.liquid`. The layout name `none` renders the page with no layout. A missing layout falls back to `site`: see [Pages and menus](/member-sites/pages-and-menus#pick-a-layout).

A layout prints the page where it writes `content_for_layout`, and Fluid's head content where it writes `content_for_header`:

```liquid layouts/site.liquid
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>{{ page.title }} | {{ site.name }}</title>
    {{ content_for_header }}
  </head>
  <body>
    {% render 'nav' %}
    {{ content_for_layout }}
    {{ 'site.js' | asset_url | script_tag }}
  </body>
</html>
```

`content_for_header` carries what the page needs in its `<head>`: the site SDK that installs `window.fluid`, and a link to `assets/site.css` when the site has that file. A page with no layout can print `content_for_header` too.

## Read the Liquid objects

A page and its layout render with the same objects.

| Object | What it holds |
| --- | --- |
| `site` | `name`, `handle`, `url` (`/accounts/<handle>`), `pages`, `pages_menu` and `menus` |
| `site.pages` | The published pages in position order. Each has `title`, `slug`, `url`, `home` and `current` |
| `site.pages_menu` | The same pages as a menu: `title`, `handle` and `menu_items`. Each item has `title`, `url` and `sub_menu_items` |
| `site.menus.<slug>` | A menu from `config/menus.json`, in the same shape, such as `site.menus.footer` |
| `settings` | The published `config/settings.json`, plus `settings.menu`, which is the page's menu, else the menu with the slug `main`, else `site.pages_menu` |
| `page` | The page being rendered, shaped like an entry of `site.pages` |
| `company` | `id` and `name` |

- **Every `url` is a path on your company's domain**, such as `/accounts/rileys-shop/about`. Use it as written in links.
- **An unpublished page isn't listed.** A page with `published: false` isn't in `site.pages`, `site.pages_menu` or any menu.
- **Don't read member data in Liquid.** Don't read `member` or `member.<field>` in a layout, section, snippet or page. Member data is leaving member site Liquid, and `fluid member-site lint` warns on every `member.<field>` it finds. Read the viewer's data in a script.
- **Keep members' data out of settings.** `config/settings.json` is the same for every viewer.

A navigation snippet reads `settings.menu`:

```liquid snippets/nav.liquid
<nav>
  {% for item in settings.menu.menu_items %}
    <a href="{{ item.url }}">{{ item.title }}</a>
  {% endfor %}
</nav>
```

## Use tags and filters

A site's Liquid reaches its own files only.

| You write | It resolves to |
| --- | --- |
| `{% render 'card' %}` | `snippets/card.liquid` |
| `{% section 'hero' %}` | `sections/hero.liquid` |
| `{{ 'site.css' \| asset_url }}` | The address of the site's `assets/site.css` |
| `{{ 'site.js' \| asset_url \| script_tag }}` | A `<script>` element for `assets/site.js` |
| `{{ 'page.css' \| asset_url \| stylesheet_tag }}` | A `<link>` element for `assets/page.css` |
| `{{ content_for_layout }}` | The rendered page, inside a layout |
| `{{ content_for_header }}` | The site's head content, inside a layout or a page |

A page template can use a section, a snippet and a settings value together:

```liquid pages/index.liquid
{% section 'hero' %}
<main style="color: {{ settings.primary_color }}">
  <h1>{{ site.name }}</h1>
  {% render 'card' %}
</main>
```

Sections can carry a `{% schema %}` block. Lint checks it, and the pairing of block tags such as `{% if %}` and `{% endif %}`.

A page has a limit on Liquid work, which its layout, page and sections share. A runaway loop, or a page that renders too many sections, stops where the limit runs out. The page still loads, and the part that ran out renders nothing or shows `Liquid error: Memory limits exceeded`.

<Warning>
  Load a site's JavaScript with `script_tag`, or add `crossorigin="anonymous"` to a hand-written `<script src>`. Fluid serves a site's script only to a request from the site's own frame, which sends `Origin: null`. A plain `<script src>` sends no origin, and Fluid answers it with `404`. A `<script>` element with the code inline works either way.
</Warning>

## Know the frame's rules

Every page renders in an iframe on your company's domain with this policy:

```text
Content-Security-Policy: frame-ancestors 'self'; sandbox allow-scripts allow-forms
```

The sandbox never allows the same origin, so the page has an opaque origin. Your code runs freely inside it. These rules follow:

- **No cookies and no storage.** A site's JavaScript has no cookie, and reading `document.cookie` throws. It has no `localStorage` or `sessionStorage`. Don't build sign-in, "remember me" or any state that relies on them, and never put a token or other credential in Liquid, settings or an asset.
- **Scripts and forms only.** The sandbox grants scripts and forms. The browser also blocks popups, `alert` and `confirm` dialogs, and navigation of the top page.
- **Fluid draws the account menu.** It appears outside the frame on every page, even a page with the layout `none`. No template can hide or replace it, so don't build a second account menu or a sign-out link.
- **Link inside the site.** Use `site.pages` and menu `url` values. A click navigates inside the frame.
- **Reach Fluid with `fluid.fetch`.** The frame has no cookie, so the page's own `fetch` to a Fluid API carries no session and fails. Call `window.fluid.fetch(path, init)` instead, which behaves like `fetch`. See [Read viewer data in site scripts](/member-sites/site-scripts).

## Use text assets only

A site holds text assets only: `css`, `js`, `json`, `txt` and `html` files in `assets/`, valid UTF-8 and not empty. A push refuses any other file.

Don't put an image, a font, a PDF or a video in the folder, and don't inline one as a large base64 string. Upload images and fonts to your company's media library and use the URL it gives you, in an `<img src>`, in `background-image: url(...)` and in an `@font-face` `src`.

```css assets/site.css
@font-face {
  font-family: "Riley Serif";
  src: url("https://media.example.com/fonts/riley-serif.woff2") format("woff2");
}

.hero {
  background-image: url("https://media.example.com/images/hero.jpg");
}
```

An asset has no draft. A new, changed or removed asset is live on a published site as soon as a push writes it, so write assets that still work with the published pages. See [Know what is live at once](/member-sites/cli#know-what-is-live-at-once).

## Preview and publish

Page content, layouts, sections, snippets and settings are drafts until you publish the site, and members see only the published copies. See [Publish a site](/member-sites/publishing). To see a draft, run `fluid member-site dev`, or use the draft preview operations of the [member API](/api-reference/site-preview/preview-the-home-page-of-a-sites-draft) or the [company API](/api-reference/member-site-preview/preview-the-home-page-of-a-company-sites-draft).
