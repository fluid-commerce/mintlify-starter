A site is a small set of Liquid layouts, sections, snippets, pages and text assets that Fluid serves to your members. This guide builds one with the API: create it, write its files, add pages, then publish.

<Note>
  Member sites must be turned on for your company by Fluid. Until they are, every route in this guide returns `404`. To ask for them, [contact support](/help/getting-help).
</Note>

## Choose the route

Two APIs build sites. The owner of the site decides which one you use.

| Owner | Base path | Credential |
| --- | --- | --- |
| A member | `/api/member/v2026-10/sites` | The member's own credential |
| The company | `/api/company/v2026-10/member-sites` | A signed-in admin who may change themes |

- **Each API reaches one kind of site.** The member API reaches only the sites the signed-in member owns. Another member's site, and any site in another company, returns `404`.
- **A company admin can't change a member's site.** The company API lists, reads, takes down, deletes and copies a member's site. Its file, page and publish routes answer `403` for one, reads included.
- **A member's credential can't change a company site.** Use the company API for those.

Both APIs send the credential as a Bearer token to `https://api.fluid.app`. See [Member APIs](/api/member-apis#credentials) for the member credentials and [Authentication](/api/authentication) for tokens.

## What a site holds

Files use theme-style paths, with no subfolders:

| Path | What it is |
| --- | --- |
| `layouts/<name>.liquid` | A layout. `layouts/site.liquid` is the site's own default |
| `sections/<name>.liquid` | A section |
| `snippets/<name>.liquid` | A snippet |
| `pages/<slug>.liquid` | A page's content. `pages/index.liquid` is the home page |
| `assets/<file>` | A text asset: css, js, json, txt or html |
| `config/settings.json` | The site's settings, a JSON object |
| `config/menus.json` | The site's menus. Writing it replaces every menu |
| `config/pages.json` | The site's default layout and its page settings |

Names use lowercase letters, digits, hyphens and underscores. A path outside these is refused with `422`. Layouts, sections, snippets and pages are saved as drafts until you publish the site.

## Build a member's site

The examples use `$MEMBER_TOKEN` for the member's credential and `$SITE_ID` for the site's `id`.

<Steps>
  <Step title="Create the site">
    [Add a site](/api-reference/sites/add-a-site) with a name. The site starts as a private draft. Without a `handle`, Fluid proposes one from the name.

    ```bash
    curl -X POST "https://api.fluid.app/api/member/v2026-10/sites" \
      -H "Authorization: Bearer $MEMBER_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{ "name": "Riley'\''s Shop", "visibility": "private" }'
    ```

    ```json
    {
      "status": 201,
      "data": {
        "id": "0192f4e5-6f7a-7b8c-9d0e-1f2a3b4c5d67",
        "handle": "rileys-shop",
        "name": "Riley's Shop",
        "visibility": "private",
        "status": "draft",
        "owner_kind": "member",
        "copied_from_id": null,
        "layout_name": null,
        "settings": {},
        "content_version": "0192f4e5-6f7a-7b8c-9d0e-1f2a3b4c5d68",
        "lock_version": 0
      }
    }
    ```

    A handle is lowercase letters and digits separated by single hyphens, at most 40 characters. The site keeps its `id` if you change the handle later. A member can own at most 25 sites.

    The request returns `422` for a missing or blank name, a handle that is malformed, reserved or already used, an unknown field, or when the member already owns 25 sites.
  </Step>
  <Step title="Write the files">
    [Write a site file](/api-reference/site-files/write-a-site-file) with `PUT`. The path is in the URL and the body holds the whole new content. The same call creates a file and replaces one.

    ```bash
    curl -X PUT "https://api.fluid.app/api/member/v2026-10/sites/$SITE_ID/files/layouts/site.liquid" \
      -H "Authorization: Bearer $MEMBER_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{ "content": "<main>{{ content_for_layout }}</main>", "must_not_exist": true }'
    ```

    ```json
    {
      "status": 200,
      "data": {
        "path": "layouts/site.liquid",
        "content": "<main>{{ content_for_layout }}</main>",
        "lock_version": null,
        "version": "4c4127c0f28a648e32ccb71b3b6d1c7cf4c8c8cf8d4459c25a14dfab782049de"
      }
    }
    ```

    Every file has a `version`. Send it back as `version` to write the file only if it hasn't changed since you read it, or send `must_not_exist` to create the file only if the path is free. Send one of them, not both. With neither, the write replaces whatever is there and the last write wins.

    `config/settings.json` is versioned by the settings' `lock_version`. Send that when you write it.

    The request returns `409` when the `version` is stale or the file already exists under `must_not_exist`. It returns `422` for a path that isn't supported, an asset that isn't a text file or is empty, settings that aren't a JSON object, or a template that is invalid.

    [List a site's files](/api-reference/site-files/list-a-sites-files) returns each file's `path`, `kind` and `version` without its content, a page at a time. Read one with [Show a site file](/api-reference/site-files/show-a-site-file). Remove a layout, section, snippet or asset with [Remove a site file](/api-reference/site-files/remove-a-site-file), which takes the file's `version` in the query.
  </Step>
  <Step title="Add pages">
    [Add a page](/api-reference/site-pages/add-a-page) creates the page and the file that holds its content in one step. Send the content as `content`.

    ```bash
    curl -X POST "https://api.fluid.app/api/member/v2026-10/sites/$SITE_ID/pages" \
      -H "Authorization: Bearer $MEMBER_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{ "slug": "about", "title": "About us", "published": true, "content": "<h1>About us</h1>" }'
    ```

    ```json
    {
      "status": 201,
      "data": {
        "id": "0192f4e5-7a01-7b8c-9d0e-1f2a3b4c5d02",
        "slug": "about",
        "title": "About us",
        "position": 0,
        "published": true,
        "layout_name": null,
        "menu": null,
        "lock_version": 0
      }
    }
    ```

    A slug is lowercase letters and digits separated by single hyphens, or `/` for the home page. `index` is reserved for the home page. A page is shown only once its `published` is `true` and the site is published. A site holds at most 50 pages.

    To change a page, [change it](/api-reference/site-pages/change-a-page) with `PATCH` and the page's `lock_version`. A new slug renames the page's file with it. To remove one, [remove the page](/api-reference/site-pages/remove-a-page). The file route can't remove a page's file.

    The request returns `409` when a `lock_version` is stale. It returns `422` for a missing field, a malformed, reserved or taken slug, a menu that isn't one of the site's, an unknown field, or when the site already holds 50 pages.
  </Step>
  <Step title="Publish the site">
    [Publish a site](/api-reference/sites/publish-a-site) with no body. It publishes the drafts of the site's layouts, sections, snippets, pages and settings, marks the site `published` and replaces its `content_version`. Publishing again publishes the current content again.

    ```bash
    curl -X POST "https://api.fluid.app/api/member/v2026-10/sites/$SITE_ID/publish" \
      -H "Authorization: Bearer $MEMBER_TOKEN"
    ```

    The request returns `200` with the site. It returns `409` on a conflict, such as a change made while the site was being published. Run it again. It returns `422` if a company admin took the site down, because its owner can't publish it again.

    A write to an asset or to `config/menus.json` takes effect without a publish.
  </Step>
</Steps>

### Change, copy and delete a site

- **Change.** [Change a site](/api-reference/sites/change-a-site) with `PATCH` to rename it or change its `handle`, `visibility`, `layout_name` or `settings`. Send the `lock_version` you last read, so the change is refused with `409` if the site changed since. A page change or a write to `config/menus.json` also moves the site's `lock_version`, so read the site again before a versioned change. The request returns `422` for an empty body.
- **Copy.** [Copy a site](/api-reference/sites/copy-a-site) makes a private draft the member owns from a site's published content. A member can copy a site they own, and a published site shared with them with `copy` permission. The body is optional and takes a `name` and a `handle`. The copy counts toward the 25-site limit. It returns `403` when the member may open the site but not copy it, and `404` when they can't open it.
- **Delete.** [Delete a site](/api-reference/sites/delete-a-site) removes the site and its pages. It returns `204`.

### Errors

| Status | Meaning |
| --- | --- |
| `401` | The credential is missing or unusable |
| `403` | The credential is read-only. A member session JWT or a portal JWT is refused on every write |
| `404` | No site of the member's has this id, or member sites aren't turned on for the company |
| `409` | The site, page or file changed since you read it. Read it again and retry |
| `422` | The request was refused. `error.details` is keyed by the field at fault |

Errors share one envelope with `status`, `error.message`, `error.details` and `meta`. Successful responses carry a `meta` object too, with a `request_uuid` and a `timestamp`. A site and a page also carry `created_at` and `updated_at`. The examples leave these out.

## Build a company site

Company sites use the company API, which wraps each body and each response in a named key, `member_site`, `member_site_file` or `member_site_page`, instead of `data`. Write each body as `{ "member_site": { ... } }`.

- **Reads** need the `application_themes.view` permission. A droplet installation token with the `website` scope can read sites and pages.
- **Writes** need the `application_themes.update` permission and a signed-in admin. A company API token and a droplet installation token can't write. Files hold a site's code, so reading them needs a signed-in admin too.

The examples use `$ADMIN_TOKEN` for an admin's own session token, sent as a Bearer token.

| Task | Request |
| --- | --- |
| Create a site | `POST /api/company/v2026-10/member-sites` |
| List sites | `GET /api/company/v2026-10/member-sites` |
| Change a site | `PATCH /api/company/v2026-10/member-sites/{id}` |
| Write a file | `PUT /api/company/v2026-10/member-sites/{id}/files/{path}` |
| Add a page | `POST /api/company/v2026-10/member-sites/{id}/pages` |
| Publish a site | `POST /api/company/v2026-10/member-sites/{id}/publish` |
| Copy a site | `POST /api/company/v2026-10/member-sites/{id}/copy` |
| Take a site down | `POST /api/company/v2026-10/member-sites/{id}/take-down` |
| Delete a site | `DELETE /api/company/v2026-10/member-sites/{id}` |

Files and pages follow the same rules as a member's site: the same paths, the same `version` and `lock_version` checks, and the same limit of 50 pages. Only the wrapper keys differ.

<Steps>
  <Step title="Create the site">
    Create a company site as a draft. An admin can set `required` and `position` on it, which a member can't.

    ```bash
    curl -X POST "https://api.fluid.app/api/company/v2026-10/member-sites" \
      -H "Authorization: Bearer $ADMIN_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{ "member_site": { "name": "Fall Launch", "visibility": "public", "required": true, "position": 2 } }'
    ```

    ```json
    {
      "member_site": {
        "id": "019a2b3c-4d5e-7f6a-8b7c-9d0e1f2a3b4c",
        "handle": "fall-launch",
        "name": "Fall Launch",
        "owner_kind": "company",
        "owner_member": null,
        "copied_from_id": null,
        "visibility": "public",
        "status": "draft",
        "taken_down_at": null,
        "required": true,
        "position": 2,
        "layout_name": null,
        "settings": {},
        "content_version": "019a2b3c-5e6f-7a7b-8c9d-0e1f2a3b4c5d",
        "lock_version": 0
      },
      "status": 201
    }
    ```

    The request returns `403` when the caller lacks the permission or isn't a signed-in admin. It returns `422` for invalid parameters or a handle that is taken, reserved or malformed.
  </Step>
  <Step title="Write files and add pages">
    Write each file with `PUT` and add each page with `POST`. The body wraps the same fields in `member_site_file` or `member_site_page`.

    ```bash
    curl -X PUT "https://api.fluid.app/api/company/v2026-10/member-sites/$SITE_ID/files/layouts/site.liquid" \
      -H "Authorization: Bearer $ADMIN_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{ "member_site_file": { "content": "<main>{{ content_for_layout }}</main>", "must_not_exist": true } }'
    ```

    ```bash
    curl -X POST "https://api.fluid.app/api/company/v2026-10/member-sites/$SITE_ID/pages" \
      -H "Authorization: Bearer $ADMIN_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{ "member_site_page": { "slug": "launch", "title": "Launch", "published": true, "content": "<h1>Launch</h1>" } }'
    ```

    Both return the saved record under `member_site_file` or `member_site_page`:

    ```json
    {
      "member_site_file": {
        "path": "layouts/site.liquid",
        "content": "<main>{{ content_for_layout }}</main>",
        "lock_version": null,
        "version": "4c4127c0f28a648e32ccb71b3b6d1c7cf4c8c8cf8d4459c25a14dfab782049de"
      },
      "status": 200
    }
    ```

    ```json
    {
      "member_site_page": {
        "id": "019a2b3c-9b0c-7d1e-8f2a-4b5c6d7e8f91",
        "slug": "launch",
        "title": "Launch",
        "position": 0,
        "published": true,
        "layout_name": null,
        "menu": null,
        "lock_version": 0
      },
      "status": 201
    }
    ```

    They return `403` for a member's site, `409` for a stale version, and `422` for a refused request.
  </Step>
  <Step title="Publish the site">
    ```bash
    curl -X POST "https://api.fluid.app/api/company/v2026-10/member-sites/$SITE_ID/publish" \
      -H "Authorization: Bearer $ADMIN_TOKEN"
    ```

    ```json
    {
      "member_site": {
        "id": "019a2b3c-4d5e-7f6a-8b7c-9d0e1f2a3b4c",
        "handle": "fall-launch",
        "name": "Fall Launch",
        "owner_kind": "company",
        "owner_member": null,
        "copied_from_id": null,
        "visibility": "public",
        "status": "published",
        "taken_down_at": null,
        "required": true,
        "position": 2,
        "layout_name": null,
        "settings": {},
        "content_version": "019a2b3c-8a9b-7c1d-8e2f-3a4b5c6d7e8f",
        "lock_version": 3
      },
      "status": 200
    }
    ```

    The request returns `200` with the site under `member_site`. It returns `403` for a member's site, because its owner publishes it. It returns `409` on a conflict, such as a change made while the site was being published, and `422` when an admin took the site down.
  </Step>
</Steps>

### Oversee member sites

- **List.** The list covers every site in the company, filtered with `filter[owner_kind]` (`company` or `member`) and `filter[status]` (`draft`, `published` or `taken_down`). It is paged with `page[cursor]` and `page[limit]`, 25 sites by default and at most 100.
- **Take down.** `POST /api/company/v2026-10/member-sites/{id}/take-down` sets a site's `status` to `taken_down`. Its owner can't publish it again.
- **Copy.** A copy of any site is a new private draft company site with no owner member. A company admin has no limit on the number of sites.
- **Delete.** Deleting a site of any owner removes its pages too. It returns `204`.

A site's `owner_member` is the owning member's `id` and `display_name`, or `null` for a company site. No contact details are returned.
