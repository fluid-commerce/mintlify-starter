This page takes you from nothing to a live Mist app. Pick the Mist desktop app if you'd rather chat than type commands. Pick the Fluid CLI if you work in a terminal.

## Before you start

- Your role needs the **Mist** permission that starts with **Create new Mist hostings**. See [Roles](/help/admin/settings/roles). Through the API, that's the `mist.create` permission.
- Your company needs usage credits if Fluid draws your hosting from credits. See [Billing](/mist-apps/billing).

## Build with the Mist desktop app

<Steps>
  <Step title="Create the app">
    In the left nav, click **Apps**, then click **New app**, or press Cmd+Shift+M. Enter a name, such as "Event attendance". If you see **App type**, leave the default or pick a template. Then click **Create Mist**.

    You see **Setting up your Mist Cloud environment…** while Fluid creates the repository, server and database.
  </Step>
  <Step title="Describe what you want">
    In the chat, describe the app in plain words. For example: "Build a page where members log who came to their event, and save each entry to the database."

    Mist writes the code in the app's repository on your computer.
  </Step>
  <Step title="Run it locally">
    In the preview toolbar, click **Run**. The app runs on your computer with its own local database, so your tests don't touch production data.
  </Step>
  <Step title="Publish">
    Click **Publish**. Mist pushes your changes to the app's repository, and Fluid builds and deploys them. The status shows **Live** when it's done.
  </Step>
</Steps>

For every button and message along the way, see [Mist Apps](/help/mist/mist-apps) and [Run and publish](/help/mist/run-and-publish) in the Help Center.

## Build with the Fluid CLI

<Steps>
  <Step title="Install and sign in">
    ```bash
    npm install -g @fluid-app/fluid-cli @fluid-app/fluid-cli-mist
    fluid login
    ```
  </Step>
  <Step title="Create the app">
    ```bash
    fluid mist create --name "Event attendance"
    ```

    Creating an app takes about a minute. The command prints the app's slug, such as `3bed85`, and the command to clone it.
  </Step>
  <Step title="Clone the repository">
    ```bash
    fluid mist clone 3bed85 --dir event-attendance
    cd event-attendance
    ```

    Without `--dir`, the CLI clones into a folder named after the app. It also writes a `.mist` file there, so later `fluid mist` commands in that folder don't need the slug.
  </Step>
  <Step title="Run it locally">
    ```bash
    npm install
    npm run dev
    ```

    Open `http://localhost:3000`. The app uses a local database file, so you don't need Postgres installed.
  </Step>
  <Step title="Publish">
    ```bash
    fluid mist push --watch -m "Add event attendance log"
    ```

    `push` commits your changes and pushes them to the app's repository, which starts a deployment. `--watch` follows the build until it's ready or fails.
  </Step>
  <Step title="Open the live app">
    ```bash
    fluid mist open
    ```
  </Step>
</Steps>

To see every `fluid mist` command and its flags, run `fluid mist --help`.

## Create from the admin

You can also create a Mist app on the [Mist Apps](/help/admin/settings/mist-apps) screen in the admin. Click **Create Mist**, enter a **Name** and click **Create**. Then open the app in Mist or clone it with the CLI to build it.

## Create through the API

Send a request to [Provision a new Mist](/api-reference/mists/provision-a-new-mist) with a company admin Bearer token. The response returns the app in the `provisioning` state with its final public address. Poll [Show one Mist](/api-reference/mists/show-one-mist) until the state is `live`.
