A Mist app is a web app that Fluid hosts for you. You describe what you want in [Mist](/help/mist), Fluid's AI assistant, and Mist writes the code, runs it on your computer and publishes it. You don't need to set up a server, a database or a deployment pipeline.

Mist apps are the fastest way to build on Fluid. A merchant can ask for "an app that lets members log event attendance" and get a working, hosted app without writing code. A developer gets a real codebase to read, change and push.

## What Fluid sets up for you

When you create a Mist app, Fluid provisions everything the app needs in one step:

| Resource | What you get |
| --- | --- |
| Code repository | A private Git repository generated from the public [starter template](/mist-apps/starter-template). |
| Server | Hosting for the app, with a public address and HTTPS. Every push to the repository's `main` branch builds and deploys the app. |
| Database | A dedicated Postgres database for the app. |
| Environment variables | The database connection and Fluid connection values, set on the server for you. |
| Fluid tokens | A private API token and a public token for your company, so the app can call the Fluid API on day one. |

See [Hosting, database and environment variables](/mist-apps/hosting) for the details.

## Authentication is already built in

The starter template ships the parts of a Fluid integration that are easiest to get wrong:

- Verified webhooks, with HMAC signatures and replay protection.
- The droplet install flow, which exchanges a short-lived install token for the company's credentials.
- Per-installation tenancy, so each company's data stays separate.
- Viewer identity for pages embedded in Fluid, from a signed session token.

You build features on top of them. See [Authentication](/mist-apps/authentication).

## Where a Mist app shows up

A new Mist app is standalone: a web app at its own address. To put it inside Fluid, add an integration point:

- **Droplet**: an app inside the Fluid admin.
- **Drop Zone**: a block injected into a zone, such as checkout or order confirmation.
- **Mobile**: an embed inside the Fluid mobile app.

See [Integration points](/mist-apps/integration-points).

## Mist app, portal widget or theme?

| You want to | Build |
| --- | --- |
| Run your own server code, store your own data, or receive webhooks | A Mist app |
| Add a tool to the admin, a block to checkout, or a page to the mobile app | A Mist app with an integration point |
| Add reusable UI to the portal your members use, with no server of your own | A [widget package](/portal-widgets/overview) |
| Change how your storefront looks | A [theme](/themes/overview) |

## Ways to work with Mist apps

- **Mist desktop app**: create, run, publish and manage apps by chatting. See [Mist Apps](/help/mist/mist-apps) in the Help Center.
- **Fluid admin**: list your company's apps and create new ones on [Mist Apps](/help/admin/settings/mist-apps).
- **Fluid CLI**: the `fluid mist` commands, for developers who work in a terminal.
- **API**: every developer workflow is also available through the [Mist apps API](/api-reference/mists/provision-a-new-mist).
