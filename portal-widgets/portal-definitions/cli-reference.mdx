---
title: "Portal Definition CLI workflows"
description: "Use the supported Fluid portal commands for Portal Definition authoring and release."
---

Run `fluid portal <command> --help` for the exact options installed in your project.

| Command | Effect |
| --- | --- |
| `fluid portal create <app-name>` | Creates a new portal project. |
| `fluid portal clone [app]` | Clones the provisioned repository for an existing definition. |
| `fluid portal dev` | Previews local portal resources. |
| `fluid portal pull` | Reads the remote working definition into `portal/`. |
| `fluid portal push` | Validates and writes the remote working definition. |
| `fluid portal doctor` | Reports drift in generated project files. |
| `fluid portal version create` | Creates an immutable snapshot of the working definition. |
| `fluid portal version list` | Lists the definition's versions. |
| `fluid portal version activate <version-id>` | Makes a selected version live. |

## Identify a definition

`pull` and `clone` can select by name or ID. Prefer `--id` when names repeat.

```bash
fluid portal pull --id <definition-id>
fluid portal clone --id <definition-id>
```

## Separate local, draft, and live effects

- `dev` and `doctor` are local checks.
- `pull` reads remote draft state.
- `push` writes remote draft state.
- `version create` makes an immutable snapshot.
- `version activate` changes the live definition.

Portal Definition commands do not publish Widget Packages. Company Widget Packages use `fluid portal widget create` and `fluid portal deploy`; see the [company package quickstart](/portal-widgets/widget-packages/company-quickstart).
