Run the relevant command with `--help` for the exact options installed in your project.

## Company packages

| Command | Effect |
| --- | --- |
| `fluid portal widget create <name>` | Scaffolds a company widget in a portal project. |
| `fluid portal dev` | Runs the portal host and local widget-development integration. |
| `fluid portal deploy --dry-run` | Builds and validates company publication artifacts without uploading. |
| `fluid portal deploy` | Publishes company widget runtime artifacts. |

The portal command tree has no Widget Package `publish` command. Use `portal deploy` for this package model.

## Standalone Droplet packages

| Command | Effect |
| --- | --- |
| `fluid widget create <project-name>` | Creates a standalone widget project. |
| `fluid widget clone <package>` | Clones a package's provisioned repository. |
| `fluid widget link` | Associates the project with an existing Droplet. |
| `fluid widget dev` | Serves local package and worker endpoints. |
| `fluid widget validate` | Validates package metadata and source configuration. |
| `fluid widget build` | Validates, type checks, and builds publication artifacts. |
| `fluid widget push` | Commits and pushes your source to the package's repository, then builds and publishes an immutable Droplet package version. Use it to publish. |
| `fluid widget publish` | Builds and publishes a package version without committing or pushing source. The template's `widget:publish` script runs it. |
| `fluid widget status` | Shows package publication status for a Droplet. |
| `fluid widget logs` | Shows recent publication logs. |

## Use push carefully

`fluid widget push` has separate source-synchronization and publication phases. Its options:

| Option | Effect |
| --- | --- |
| `-m, --message <message>` | Commit message for the automatic commit. The default is a timestamped publish message. |
| `--no-commit` | Push existing commits without making a new one. |
| `--branch <name>` | Branch to push. The default is `main`. |
| `--skip-publish` | Synchronize the repository only. |
| `--droplet <uuid>` | Droplet that owns the package, when the project doesn't name it. |
| `--dry-run` | Build and validate the publish step without uploading. Source synchronization still runs. |

Repository divergence stops before publication. Source synchronization can succeed before publication fails. Read the phase result before retrying; do not assume either phase rolled back the other.

Use `fluid widget publish --dry-run` when you need to validate publication without synchronizing source or writing a remote package version.
