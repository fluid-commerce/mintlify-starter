---
title: "Choose a Widget Package model"
description: "Choose between a company package in a portal project and a standalone package linked to a Droplet."
---

Fluid supports two Widget Package lifecycles. Both use the Widget Worker SDK, but their owners, configuration, and publication commands differ.

Both models define package metadata through [`DefineWidgetPackageOptions`](/portal-widgets/reference/widget-worker-sdk/types/DefineWidgetPackageOptions).

| | Company package | Standalone Droplet package |
| --- | --- | --- |
| Location | Inside a generated portal project | In its own widget project |
| Owner | Company | Existing Droplet |
| Package configuration | `src/widgets.config.ts` | `manifest.ts` and `fluid.widget.config.ts` |
| Scaffold command | `fluid portal widget create` | `fluid widget create` |
| Publish command | `fluid portal deploy` | `fluid widget publish` |

## Choose a company package

Use a company package when the widgets belong to one company's portal development project and should publish through that portal's widget catalog.

</Card>

## Choose a Droplet package

Use a standalone package when the package belongs to an existing Droplet and needs its own source repository and release lifecycle.

<Card title="Droplet package quickstart" icon="droplet" href="/portal-widgets/widget-packages/droplet-quickstart">
Link a standalone project to a Droplet and publish an immutable package version.
</Card>

## Keep the lifecycles separate

Do not copy configuration between the two project types. A standalone `fluid.widget.config.ts` does not configure a company package, and `fluid portal deploy` does not publish a Droplet package.

Use a server application instead of either package model when you need secrets, OAuth, private APIs, webhooks, or background work.
