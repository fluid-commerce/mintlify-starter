Import the supported Widget Worker SDK from one entry point:

```ts
import {
  defineWidget,
  defineWidgetPackage,
  startWidgetPackage,
} from "@fluid-app/portal-sdk/widgets/worker";
```

Use the generated [`defineWidget`](/portal-widgets/reference/widget-worker-sdk/functions/defineWidget), [`defineWidgetPackage`](/portal-widgets/reference/widget-worker-sdk/functions/defineWidgetPackage), and [`startWidgetPackage`](/portal-widgets/reference/widget-worker-sdk/functions/startWidgetPackage) references for exact fields, types, and return values.

## Define one widget

```ts
const teamStatus = defineWidget({
  name: "TeamStatus",
  component: TeamStatus,
  displayName: "Team status",
  description: "Shows current progress for a member's team.",
  category: "components",
  container: "card",
  defaultProps: {
    title: "This month's progress",
  },
  propertySchema: {
    fields: [
      {
        key: "title",
        label: "Title",
        description: "Heading shown above the team progress summary.",
        type: "text",
        defaultValue: "This month's progress",
      },
    ],
  },
});
```

Keep the widget name stable after publication. Defaults must satisfy the property schema and render a useful initial state.

## Define a package

```ts
export const widgetPackage = defineWidgetPackage({
  scope: "partners",
  packageStableId: "team-tools",
  version: "1.2.0",
  widgets: [teamStatus],
});
```

Package ownership changes the required identity fields. Start from the generated project for your package model and use the reference for the exact options.

### Widget types

A screen places a widget by its type. A package widget's type starts with `company.` or `droplet.`, continues with the package's identity, and ends with the widget's `name`. That keeps it apart from built-in types like `TextWidget`, which a package can never replace.

The portal loads a package only if none of its widget types is already registered. If one is, because two packages share an identity, the portal skips the whole package. It logs a warning in the browser console and shows nothing on the page. Keep each package's identity unique, and each widget `name` unique within its package.

A screen node whose type no loaded package provides renders nothing. Check that the package is published and available to the portal. See [Droplet package visibility](/portal-widgets/widget-packages/droplet-quickstart#when-the-package-appears-in-a-portal).

## Start the worker

The generated worker entry starts every registered widget:

```ts
startWidgetPackage(widgetPackage);
```

Keep values that cross the worker boundary JSON-serializable according to the SDK types. Do not author runtime URLs or generated package descriptors; build and publication own them.
