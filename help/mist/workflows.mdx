A workflow is a chain of steps that Mist runs for you. Each step runs a skill or a written instruction in its own chat. After each step, a separate reviewer checks the result against the step's acceptance criteria, and sends the step back for rework if it falls short.

Use workflows for big jobs with many parts, such as opening a country or launching a new store.

## Workflows you can run

Fluid publishes workflows in the public Mist Skills repository, and Mist downloads them each time it starts. They include:

- **Open a Country**, plus a finalizing workflow for each way of operating in a country.
- **Speed Import**
- **Streamlined Onboard & Launch**

For the full list, see [Mist Skills](/guides/mist-skills#workflows).

Workflows you build yourself are saved in the `Fluid/workflows` folder in your home folder. A workflow you save there with the same name as a Fluid workflow replaces Fluid's version on your computer.

## Run a workflow

<Steps>
  <Step title="Open the library">
    In the sidebar, click **Workflows**. Type in **Search workflows** to filter the list.
  </Step>
  <Step title="Open the workflow">
    Click the workflow to read its steps.
  </Step>
  <Step title="Run it">
    Click **Run**.
  </Step>
</Steps>

You can also start a workflow from the chat. Type **/**, then pick a row marked **Workflow**. The run starts as soon as you pick it.

Some workflows start from a skill that asks you questions first. For example, the **Open a Country** skill asks which country and how you'll operate there, then starts the **Open a Country** workflow with your answers.

<Warning>
  Workflows make real changes to your company, and each step uses AI, which your company pays for. While [Safe Mode](/help/mist/safe-mode) is on, Mist can't start a workflow from the chat, and any step that would change production is blocked.
</Warning>

## Follow a run

Your runs are listed under **Workflows** in the sidebar. Open a run to see each step and its status:

| Status | Meaning |
| --- | --- |
| **Pending** | The step is waiting for the steps it depends on. |
| **Working** | The step is running. |
| **QA review** | The reviewer is checking the step. |
| **Reworking** | The step failed review and is being fixed. |
| **Passed QA** | The step passed review. |
| **Needs review** | The step still failed review after its rework rounds. A person should check it. |
| **Failed** | The step failed. |
| **Skipped** | The step didn't run. |
| **Cancelled** | You cancelled the run. |

When a run ends, it shows **Succeeded**, **Succeeded with issues**, **Failed after partial completion**, **Cancelled** or **Interrupted**.

While a run is going, use **Pause run**, **Resume run** and **Cancel run**. When it's done, use **Run again**. The **More run actions** menu has **Copy diagnostic summary**, **Copy review** and **Agent troubleshoot**, which help you or Fluid support find out what went wrong.

## Build a workflow

<Steps>
  <Step title="Start a new workflow">
    In the **Workflows** library, click **New workflow**. Enter a name in **Name your workflow**.
  </Step>
  <Step title="Add steps">
    Click **Add step**. For each step, choose **Describe it** and write what the step should do, or **Use a skill** and pick one under **Choose a skill…**.
  </Step>
  <Step title="Say what done looks like">
    Write the step's acceptance criteria, one per line. The reviewer checks the step against them.
  </Step>
  <Step title="Set the review">
    Choose how strictly to review the step: **Strictly**, **Normally** or **Loosely**. Under **If it still fails**, choose **Keep going and flag it for review** or **Stop the workflow here**.
  </Step>
  <Step title="Choose where the step runs">
    Under **Runs in**, choose **The project it was started from**, or a type of project, such as a theme.
  </Step>
  <Step title="Save it">
    Click **Save**.
  </Step>
</Steps>

Steps run from top to bottom, and each waits for the one above it. To run a step at the same time as the step above, turn on **Runs alongside the step above**.

Use **Import** and **Export** to share a workflow as a file. You can also ask Mist in the chat to build a workflow for you.

## Limits

- A workflow runs up to 5 steps at the same time by default, and at most 10.
- A step gets up to 2 rework rounds by default, and at most 5.
- Each step needs either a description or a skill, but not both.
- A step that's reviewed needs at least one acceptance criterion.
