Fluid runs Lighthouse scans on your storefront pages and keeps the latest result for each one. Use those results to find what slows a page down, fix it in your theme, and show the difference.

## What Fluid scans

Fluid scans the public storefront page of these items: products, enrollment packs, categories, collections, pages, posts, playlists, and media items. A scan measures the page the way a shopper on a phone loads it, using Google PageSpeed with the mobile form factor. Fluid loads the page once first, so the measurement reads a cached page rather than its first build.

A scan measures the live page, so it measures your published theme. Changes in an unpublished theme or a `fluid theme dev` development theme don't show up in a scan until you publish them.

Fluid queues a scan when you create or update one of these items. Changing your theme doesn't change the items, so after a theme change you request the scan yourself.

## Read the latest result

Get the latest result for the item behind the page, for example a product:

```bash
curl "https://api.fluid.app/api/v202604/company/products/48213/lighthouse" \
  -H "Authorization: Bearer <token>"
```

The result carries three summaries, worked out from the full Lighthouse report that comes with them:

- **Category scores**, from 0 to 100, for performance, accessibility, best practices and SEO.
- **Core metrics**, such as Largest Contentful Paint, Cumulative Layout Shift and Total Blocking Time, with a `good`, `needs-improvement` or `poor` rating where Lighthouse gives one.
- **Optimization opportunities**: the audits that found savings, largest saving first. Start at the top of this list.

Any value can be empty when the run didn't produce it. When no scan exists yet, the request starts one and tells you to check back. See the reference pages for each item type:

## Fix what the scan finds

Each opportunity has a Lighthouse audit ID. These are the ones a theme most often causes, and the theme fix for each:

| Audit ID | What to change in your theme |
| --- | --- |
| `uses-optimized-images`, `modern-image-formats`, `uses-responsive-images` | Request a rendition sized for the layout with the [`image_url` filter](/themes/image-transformations), for example `width: 800, format: "auto"`, or render the image with the [`media_tag` filter](/themes/media-tag), which builds a `srcset` for you. Set `sizes` to the width the image really takes up. |
| `offscreen-images` | Lazy-load images below the first screen. `media_tag` adds `loading="lazy"` by default. |
| `largest-contentful-paint-element`, `lcp-lazy-loaded` | Don't lazy-load the hero image or the first product image. Pass `loading: "eager"` to `media_tag` for that one image. |
| `unsized-images`, `layout-shifts` | Give images a `width` and `height`, or a fixed aspect ratio in CSS, so the page doesn't move as they load. `media_tag` adds both attributes when it knows the image's size. |
| `render-blocking-resources` | Load scripts with `defer` or `async`, and keep only the CSS the first screen needs in the `<head>`. Check app embeds and other markup in the head too. See [Common pitfalls](/themes/common-pitfalls) for what puts markup in the `<head>`. |
| `unused-javascript`, `unused-css-rules` | Remove libraries and stylesheets the page doesn't use, or load them only on the templates that need them. |

Large media files slow every page that shows them. Compress images and videos before you upload them to the DAM.

## Scan again and compare

<Steps>
  <Step title="Record the starting point">
    Before you change anything, read the latest result and note its scan time, the performance score, and the core metrics you plan to improve.
  </Step>
  <Step title="Publish the fix">
    Make the change in your theme and publish it, so the live page carries it.
  </Step>
  <Step title="Request a scan">
    ```bash
    curl -X POST "https://api.fluid.app/api/v202604/company/products/48213/lighthouse" \
      -H "Authorization: Bearer <token>"
    ```
    The scan runs in the background. Wait a few minutes, then read the latest result again.
  </Step>
  <Step title="Check that the result is new">
    Compare the result's scan time with the one you recorded. Fluid skips a requested scan when one ran in the last few minutes or the scanner is busy, and then you get the earlier result back. If the time hasn't changed, request the scan again later.
  </Step>
  <Step title="Report before and after">
    Report the page URL, both scan times, and the before and after values for the performance score and each metric you targeted.
  </Step>
</Steps>

Lighthouse scores vary from run to run. Compare a few scans before you call a small change an improvement.
