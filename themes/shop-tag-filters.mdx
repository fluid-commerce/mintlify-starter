---
title: "Build shop tag filters"
description: "Render tag choices, product counts, and selected filters in a shop template."
---

The standard shop template exposes a `tags` list and a Tags group in `collection.filters`. Existing custom themes need markup that renders one of these sources.

## Read the available choices

The `tags` list is ordered by name, then ID. Each item contains:

| Field | Meaning |
| --- | --- |
| `id` | Tag ID to submit with the filter |
| `name` | Display name |
| `source` | Resource type where the tag originated |
| `count` | Number of distinct eligible products assigned this tag |
| `selected` | Whether the current request selects this tag ID |

Choices include only the current company's tags assigned to products eligible for the current shop. Tags assigned only to media, unassigned tags, and tags belonging to another company are excluded. The source does not restrict matching when a tag is assigned to a product.

Counts describe the full eligible catalog before selected filters and pagination. Multiple assignments of one tag to the same product count once. Selecting a category or tag does not recalculate these counts for the narrowed result set.

## Add checkboxes to the shop form

Place this markup inside your existing shop GET filter form. Keep category, price, and tag controls in the same form so they submit together.

```liquid
{% if tags.size > 0 %}
  <fieldset>
    <legend>Tags</legend>
    {% for tag in tags %}
      <label for="shop-tag-{{ tag.id }}">
        <input
          id="shop-tag-{{ tag.id }}"
          type="checkbox"
          name="filterrific[with_tag_ids][]"
          value="{{ tag.id }}"
          {% if tag.selected %}checked{% endif %}
        >
        {{ tag.name | escape }} ({{ tag.count }})
      </label>
    {% endfor %}
    <button type="submit">Apply filters</button>
  </fieldset>
{% endif %}
```

The standard HTML shop accepts repeated `filterrific[with_tag_ids][]` values. It matches any selected tag and combines that selection with other filters. Unknown IDs match nothing; submitting no tag selection removes the tag constraint.

Use tag-specific input IDs so a tag and category with the same numeric ID do not share a label target. Translate the legend and button text using your theme's locale strings. If the controls live in a rendered component, pass `tags: tags` through each render call that needs the list.

## Use a generic filter component

The Tags entry in `collection.filters` has `type: "list"`, `operator: "OR"`, and `param_name: "filterrific[with_tag_ids][]"`.

Its `values` contain `value` (tag ID), `label`, `count`, and `active`. Its `active_values` and `inactive_values` split selected and unselected choices.

Render this group alongside your other filter groups. Build submissions from each option's `param_name` and `value`; the supplied `url_to_add` contains only one filter and `url_to_remove` is empty. See the [shop template reference](/themes/theme-variables#shop-template).

## Custom shop pages

A custom page used as the shop can bypass the standard shop template and its filter handling. In that case, supply your own tag choices and send selections through the [Public Products catalog](/api-reference/storefront/public-products-catalog). Do not expose an administrative Bearer token in your theme.

Deleting a tag also removes its assignments. Review the [tag management guide](/api/guides/manage-product-tags) before removing a tag used by your filters.
