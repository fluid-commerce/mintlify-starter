<Warning>
  Member storefront is in a limited pilot. Confirm that member storefront is enabled for your company before relying on this behavior.
</Warning>

Resource sharing puts one floating **Share** button on shareable storefront pages for signed-in members. Opening it creates a share link credited to that member.

This needs no Liquid and no theme change. Once member storefront is enabled for your company, the SDK adds the button on supported pages by itself.

## Who sees the button

The SDK asks Fluid whether the current page can be shared by the current visitor, and shows the button only when the answer is yes.

| Visitor or page | Button |
| --- | --- |
| Signed-in member on a shareable page | Shown |
| Guest | Hidden |
| Company without member storefront | Hidden |
| A page that is not shareable | Hidden |

A guest triggers no request at all. The SDK skips the check when there is no member session to check, exactly as it skips price requests on a page with no member shells.

## What can be shared

The current page URL identifies what is being shared. Supported resources are products, media, pages, and playlists.

The share is always credited to the member who is signed in. It is never credited to an identity taken from the URL, so a member browsing another member's link still shares as themselves.

## Cost to the page

The button itself is small. The share dialog and its dependencies load only when a member opens it, so a page that is never shared never pays for the dialog.

## Styling

The button and dialog read the same `--fluid-account-*` custom properties as your other Fluid account surfaces, so an override you already set applies here too:

```css
:root {
  --fluid-account-primary: #2464ec;
  --fluid-account-primary-foreground: #ffffff;
  --fluid-account-font-family: "Inter", system-ui, sans-serif;
}
```

See [Theme settings and system screen styles](/themes/member-storefront/system-screen-styling) for how those values reach member surfaces from your theme settings.

## Behavior to expect

Closing the dialog does not reopen it when the page regains focus or when the member clicks elsewhere.

If your storefront also loads Fluid's account screens, you still get exactly one button and one dialog. The two runtimes coordinate rather than each adding their own control.

## Test sharing

- Open a product page as a guest and confirm no **Share** button appears.
- Sign in, reload the page, and confirm the button appears.
- Open the dialog, create a share, and confirm the link is credited to your member account.
- Close the dialog, switch tabs, and return. The dialog should stay closed.
