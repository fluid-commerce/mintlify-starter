<Warning>
  Member storefront is in a limited pilot. Confirm that member storefront is enabled for your company before publishing this tag.
</Warning>

`{% member_account %}` gives one cached header two states. A guest sees a **Sign in** link. A signed-in member sees a round avatar of their initials that opens the Passport, the member's account menu.

Use it when you want the account control without writing the markup yourself. If you would rather build your own links and styles, use `member_routes` instead — see [Sign in and sign out](/themes/member-storefront/authentication).

<Note>
  To choose where the Passport's button shows, place the Passport yourself instead. A Passport your theme places hides this tag, unless it uses `placement="off"`. See [Place and open the Passport](/themes/member-storefront/passport).
</Note>

## Add the tag

Place it in your storefront header or member layout:

```liquid
<nav class="site-header__account" aria-label="Account">
  {% member_account %}
</nav>
```

That is the whole theme change. The tag renders an empty element carrying only data, and the SDK builds the markup inside it in the browser:

```html
<fluid-member-account
  data-fluid-member-storefront
  data-account-url="https://northwind.account.fluid.app/"
  data-sign-in-url="/auth/sign_in"
  data-sign-out-url="/auth/sign_out"
  data-sign-in-label="Sign in"
  data-account-label="Account"
  data-sign-out-label="Sign out"
></fluid-member-account>
```

With member storefront disabled, the tag renders nothing at all.

The tag takes no arguments. Passing one is a template error.

## What each visitor sees

| Visitor | Result |
| --- | --- |
| Guest | A **Sign in** link to the current host's sign-in flow, which brings them back to the page they were on |
| Member | An avatar of their initials, which opens the Passport |

Initials come from the member's display name — "Alex Kim" reads AK, and "Alex" reads A. The name arrives with the session the SDK already fetches for prices and greetings, so the avatar costs no extra request.

A click on the avatar opens the Passport beside it, with the member's account, orders, subscriptions and **Sign out**. Another click closes it. You don't add a `<fluid-passport>` tag for this. When your theme does place one, that Passport hides this tag's avatar, so a member never sees two ways in. A Passport with `placement="off"` hides nothing.

The cached HTML always starts in the guest state, exactly like a member-aware section. The avatar appears only once the SDK confirms the session. An expired session or a failed request leaves **Sign in** visible.

<Note>
  The cached page never contains the member's name or initials. Both are written in the browser after the session is confirmed.
</Note>

## Keyboard and dismissal

The avatar is a button, so it works without extra theme JavaScript. The Passport it opens closes the way it does anywhere:

- **Escape** closes the Passport and returns focus to the avatar
- A click outside closes it

On a phone, the Passport opens as a bottom sheet. See [How it behaves on phones](/themes/member-storefront/passport#how-it-behaves-on-phones).

## Styling

The tag passes your theme's own settings to the avatar and to the Passport it opens: primary color, surface color, border color, and body font among them. Both match your theme with no second palette to maintain.

A storefront with no such settings falls back to neutral defaults that inherit the surrounding header's text color, so the avatar stays legible on a light or a dark header.

To go further, style these classes with your own CSS:

| Selector | Part |
| --- | --- |
| `fluid-member-account` | The element as a whole |
| `.fluid-member-account-signin` | The guest's **Sign in** link |
| `.fluid-member-account-trigger` | The button that opens the Passport |
| `.fluid-member-account-avatar` | The initials circle |

## Labels and translation

Labels are rendered by the server, so they follow your storefront's language rather than being fixed in the browser. You do not pass label text to the tag.

## Link safety

Only `https:`, `http:`, and root-relative URLs are used. Any other value falls back to a safe default, so a mistyped or hostile value cannot turn a link into a script.

## Test your header

- Load a storefront page signed out and confirm **Sign in** is visible.
- Sign in, return to that page, and confirm the avatar shows your initials.
- Click the avatar and confirm the Passport opens beside it.
- Press **Escape**, then click outside, and confirm the Passport closes both ways.
- Sign out, then follow **Sign in** from another page, and confirm you come back to that page.
- View the cached HTML as a guest and confirm it contains no member name or initials.
