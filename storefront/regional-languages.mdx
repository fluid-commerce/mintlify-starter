A regional language is a regional version of a language Fluid already supports. A company can offer Canadian French next to French, for example. It can also offer Canadian French without French. Shoppers and members pick it like any other language. Wherever it has no wording of its own, Fluid shows the base language, then English.

Fluid offers three regional languages:

| Tag | Name in Fluid | Base language |
| --- | --- | --- |
| `fr-CA` | Français (Canada) | `fr`, French |
| `es-MX` | Español (México) | `es`, Spanish |
| `pt-BR` | Português (Brasil) | `pt`, Portuguese |

<Note>
  Regional languages are behind a release gate. A company can turn one on only after Fluid turns the gate on for it. To ask for it, [contact support](/help/getting-help).
</Note>

## How a regional language works

- **It's a language of its own.** It has its own row in the company's languages. People choose it, and translations are saved under its tag.
- **It doesn't need its base language.** A company can turn on Canadian French while French is off. See [Offer only the regional language](#offer-only-the-regional-language).
- **It holds only the wording that differs.** Where it has no text of its own, Fluid reads the base language, then English. Nothing is copied, so a later French edit shows in Canadian French at once.
- **Fallback works per field and per key.** A product with a Canadian French title and no Canadian French description shows the Canadian title and the French description.
- **Its own text wins for good.** Once you save Canadian French text for a field, a later French edit to that field no longer reaches Canadian French shoppers. Update both.
- **Chinese isn't regional.** `zh-TW` is Traditional Chinese, a different script from `zh`. It keeps its own rules and never reads `zh` text.

## Tags

A regional tag is a BCP 47 language tag: the language in lowercase, a hyphen, then the region in uppercase. Write it as `fr-CA`, `es-MX` or `pt-BR`.

- **Send the exact tag to the storefront API.** It matches the `lang` value exactly, so `lang=fr-ca` isn't the same as `lang=fr-CA`. A read ignores `fr-ca` and answers in the default language. A write refuses it with `422`.
- **Cookies and browser headers may use any case.** Fluid reads `fr-ca` and `FR-CA` as `fr-CA` there.
- **A hyphen, never an underscore.** `fr_CA` isn't a regional tag. In the `fluid_locale` cookie the underscore separates the language from the country.
- **Other regional tags aren't regional languages.** Fluid reads an unlisted tag such as `fr-BE` or `en-GB` in a browser's language list as its base language. A read with an unlisted tag in `lang` or `locale` ignores it.

## How a storefront page picks its language

Fluid picks the language of each storefront page in this order. It takes the first language that the company has turned on.

1. **The `locale` query parameter, or `lang` when there's no `locale`.** Fluid saves the choice in the `locale` cookie.
2. **A saved language cookie:** `fluid_locale`, then `fluid_language`, then `locale`. Fluid reads only the first of these cookies that exists. If the company doesn't offer that language, Fluid moves on to the browser.
3. **The browser's `Accept-Language` header.** Entries are ranked by weight, ties keep the header's order, and entries weighted `q=0` are dropped. For each entry, Fluid tries the regional language first, then its base. A browser that sends `fr-CA,fr;q=0.9` gets `fr-CA` when the company offers it, and `fr` when it doesn't.
4. **The company's default language.**

A company may offer a regional language without its base. Then a request for the base language, such as `fr`, gets the regional language, such as `fr-CA`. This holds for the query parameter, a saved cookie and the browser. A browser that asks for `fr-CA` at a company that offers `fr` but not `fr-CA` still gets `fr`.

The language cookies look like this:

| Cookie | Holds | Example |
| --- | --- | --- |
| `fluid_locale` | The language, an underscore, then the country | `fr-ca_CA`, or `fr-ca_US` for a shopper reading Canadian French in the United States |
| `fluid_language` | The language tag | `fr-ca` |
| `locale` | The language tag. Fluid saves it when a query parameter picks the language, when it replaces a saved language the company no longer offers, or when it serves a regional language in place of its base | `fr-CA` |

The FairShare SDK writes `fluid_locale` and `fluid_language` when you call `updateLocaleSettings()`. It writes the language in lowercase and the country in uppercase. Don't write these cookies yourself. Use the SDK, as in [Navbar locale selector](/themes/navbar-locale-selector).

## Caching

- **Each regional language has its own cached pages.** When a cookie names the language, cached pages are kept per country and per language, so `fr-CA` pages never mix with `fr` pages.
- **A browser-only regional language skips the cache.** Suppose a visitor has no language cookie, and their browser's first choice is `fr-CA`, `es-MX` or `pt-BR`. Fluid renders their page fresh and doesn't cache it. The response carries `X-CDN-Cache: SKIP`. This holds at every company, whether or not it offers the language. Once the visitor saves a language, their pages are cached again.
- **A request for a base language served in its regional language is cached under the regional language.** Fluid saves `fr-CA` for a browser that asks for `fr` at a company that offers only `fr-CA`. The page is cached under `fr-CA`, never under `fr`.
- **Language query parameters skip the cache.** A URL with `lang` or `locale` always renders fresh. See [Query parameters and caching](/themes/query-parameters-and-caching).
- **Turning a language off clears its cached pages.**
- **Turning on a regional language while its base is off clears the base language's cached pages.** French browsers then get Canadian French, not pages cached in another language.

## Where the fallback applies

Every surface reads the regional language first. Where text is missing, it reads the base language, then English.

| Surface | What a `fr-CA` reader sees where Canadian French text is missing |
| --- | --- |
| Storefront content: products, media, categories, collections, posts, pages, playlists and enrollment packs | The French text, then the English text. This covers rich text and images set per language. |
| Lists filtered by language | A list filtered to `fr-CA` also includes records that have a French title. |
| Translated metafield values | The French translation, then the English translation, then the original value. If French is the store's default language, the original value comes straight after Canadian French. |
| Theme text from the `t` filter | `locales/fr.json`, then `locales/en.json`, then Fluid's built-in text. See [Regional theme text](/themes/developer-guide#regional-languages). |
| Fluid's built-in text, such as system emails and error messages | Fluid's Canadian French wording where it has one, then French, then English. |
| Checkout | Fluid's Canadian French checkout wording where it has one, then French, then English. |
| Country names | The French country name. |
| FairShare widgets, such as the cart and chat | The French widget text. |

Prices and Fluid's built-in date formats look the same as in the base language. Checkout is the exception for dates and point amounts: it formats them in the regional style, such as `2026-11-20` for `fr-CA`.

## Audiences

Anything you limit by language treats a regional language as part of its base:

- A person whose language is `fr-CA` also matches anything aimed at `fr`. This covers mobile app pages, mobile app navigation, mobile app share pages and widgets.
- Where a target aimed at `fr-CA` and one aimed at `fr` both apply, the `fr-CA` one wins. Widgets still follow their usual priority.
- A person whose language is `fr` doesn't match a target aimed only at `fr-CA`.
- A messaging audience aimed at `fr` also reaches members whose language is `fr-CA`, once the company has turned `fr-CA` on. An audience aimed at `fr-CA` reaches only `fr-CA` members.

## Offer only the regional language

A company can offer a regional language while its base language is off. A store for Canada, for example, can offer Canadian French and English, with French off.

- **The storefront doesn't offer French.** Its language selector lists Canadian French and the company's other languages. Checkout's language menu still lists French.
- **The fallback still reads French.** Where Canadian French has no text, Fluid shows French, then English. The French comes from French text the company already has, the theme's `locales/fr.json`, and Fluid's built-in French text.
- **A visitor who asks for French gets Canadian French.** A browser that asks for `fr` or `fr-FR`, a `?locale=fr` link, or a saved `fr` language all get `fr-CA`. Fluid then saves `fr-CA` in the `locale` cookie.
- **A cart set to French gets Canadian French.** When a cart is created in `fr`, or switched to `fr`, Fluid stores `fr-CA` on it, and checkout shows Canadian French.
- **Anything aimed at French still reaches Canadian French readers.** Matching follows the language, not the company's list. See [Audiences](#audiences).
- **New wording goes under `fr-CA`.** A save with `lang=fr` returns `422` while French is off.
- **Translate in full when there's no French text.** Where a product or page has no French text, Canadian French readers see English. Translate it into Canadian French like any other language. See [Add a language](/setup/add-a-language).

## The release gate

A release gate decides which companies can turn a regional language on. Fluid turns it on per company.

| | Gate off | Gate on |
| --- | --- | --- |
| The company's language list | Regional languages are left out, except any the company already has | Regional languages are listed |
| Turning one on | Refused as an unknown language | Allowed, whether or not its base language is on |

The gate controls only turning a regional language on. If Fluid turns the gate off later, regional languages the company already has stay on and keep working.

Whatever the gate says, you can turn a base language off while its regional language is on. You can't turn the company's default language off.

## Add a regional language with the API

These steps turn on Canadian French. For Mexican Spanish or Brazilian Portuguese, use `es-MX` or `pt-BR`. The base language can be on or off.

You need a company Bearer token with permission to update **Languages**. Every request goes to `https://api.fluid.app` with `Authorization: Bearer <token>`. The reference pages are [List company languages](/api-reference/languages/list-company-languages), [Configure company language](/api-reference/languages/configure-company-language) and [Remove company language](/api-reference/languages/remove-company-language).

<Steps>
  <Step title="List the languages and find the regional tag">
    ```bash
    curl "https://api.fluid.app/api/settings/languages" \
      -H "Authorization: Bearer <token>"
    ```

    Find the row whose `iso` is `fr-CA`. Note its `id`, and whether `active_in_company` is `true`. Look ids up by `iso` every time. Ids aren't the same in every environment.

    ```json
    {
      "languages": [
        { "id": 7, "name": "Français", "iso": "fr", "company_users_count": 214, "active_in_company": true },
        { "id": 61, "name": "Français (Canada)", "iso": "fr-CA", "company_users_count": 0, "active_in_company": false }
      ],
      "meta": { "request_id": "c4f1b9e2-7a3d-4e8b-9f21-5d6a0b3e8c47", "timestamp": "2026-11-20T15:32:08Z" }
    }
    ```

    If `fr-CA` isn't in the list, the gate is off for the company. Stop, and ask Fluid support to turn it on.
  </Step>
  <Step title="Turn the regional language on">
    Skip this step when `fr-CA` already has `active_in_company: true`. Otherwise send its `id`:

    ```bash
    curl -X POST "https://api.fluid.app/api/settings/languages" \
      -H "Authorization: Bearer <token>" \
      -H "Content-Type: application/json" \
      -d '{"id": 61}'
    ```

    A `200` response returns the language:

    ```json
    {
      "language": { "id": 61, "name": "Français (Canada)", "iso": "fr-CA", "company_users_count": 0, "active_in_company": true },
      "meta": { "request_id": "8d2e6f14-3b9a-4c71-a5e0-2f7c9d1b4e86", "timestamp": "2026-11-20T15:33:41Z" }
    }
    ```
  </Step>
  <Step title="Check the result">
    ```bash
    curl "https://api.fluid.app/api/settings/languages?active=true" \
      -H "Authorization: Bearer <token>"
    ```

    The list now includes `fr-CA`. Shoppers can choose it, and translations can be saved to it.
  </Step>
</Steps>

Don't turn `fr` on just so Canadian French has something to fall back to. The fallback works while `fr` is off.

### When a request fails

Both errors carry `error_message` and an `errors` value that says why.

| Response | `errors` | What it means | What to do |
| --- | --- | --- | --- |
| `404` | `{"language": ["Language not found"]}` | The gate is off for the company, or the `id` isn't a language. | Check the `id`. If it's right, ask Fluid support to turn the gate on. |
| `422` | A list of messages | The language is already on. | Nothing. Read `active_in_company` first, so you send only what's off. |

The exception is a regional language that's already on while the gate is off. It answers `404`, not `422`.

### Turn a regional language off

Send `DELETE /api/settings/languages/{id}` with the language's `id`, the same `id` as in the list. The order of a base language and its regional language doesn't matter. Turning `fr` off while `fr-CA` is on works, and Canadian French keeps working. You still can't turn off the company's default language, or a language that a mobile app page or mobile app navigation is limited to.

The Fluid CLI wraps these calls. `fluid translations enable fr-CA --yes` turns on Canadian French. See [Add a language](/setup/add-a-language).

## Give it its own wording

Save only the text that differs from the base language. Everything else already shows the base language. When the base language has no text for an item, see [Offer only the regional language](#offer-only-the-regional-language).

- **Storefront resources:** a translation `PATCH` with `lang=fr-CA`, such as `PATCH /api/v202604/company/products/{id}?lang=fr-CA`. See [Translations](/storefront/translations).
- **Metafield values:** the metafield translation endpoints, with `fr-CA` as the language. See [Translate metafields](/storefront/metafields#translate-metafields).
- **Theme text:** a `locales/fr-CA.json` file with only the keys that differ. See [Regional theme text](/themes/developer-guide#regional-languages).

```bash
curl -X PATCH "https://api.fluid.app/api/v202604/company/products/60311?lang=fr-CA" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"product": {"title": "Mélange de betteraves du Québec"}}'
```

<Warning>
  Don't machine-translate the whole store into a regional language while the company has French text. The CLI's `fluid translations missing fr-CA` report lists every item that has no Canadian French text of its own, even when shoppers already see French. Saving a translation for each one copies the French text into Canadian French, and later French edits stop reaching those fields.
</Warning>

## Rules

Follow these when you add or change a regional language.

1. A regional language is one of `fr-CA`, `es-MX` or `pt-BR`. No other tag is regional.
2. Write the tag with a hyphen and an uppercase region: `fr-CA`. Send exactly that to the API.
3. A regional language doesn't need its base language. Turn on only the languages the company wants to offer.
4. Don't turn the base language on just for the fallback. The fallback works while the base language is off.
5. Turn a base language and its regional language on and off in any order.
6. Look up language ids by `iso` with `GET /api/settings/languages`. Never hard-code an id.
7. Read `active_in_company` before you send a `POST`. Send one only for a language that's off. A `422` from the `POST` usually means the language is already on.
8. If the regional tag isn't in the company's language list, the release gate is off. Don't retry. Ask Fluid support.
9. A `404` when you turn on a regional language with a correct `id` means the gate is off.
10. Where the base language has text, save regional text only where the wording differs.
11. Don't run machine translation over a whole regional language while the company has base-language text.
12. Name a regional theme file with the exact tag, such as `locales/fr-CA.json`.
13. Leave a regional key out of a theme file instead of giving it an empty value. An empty value prints a blank space, not the base language's text.
14. Set a shopper's language with the FairShare SDK's `updateLocaleSettings()`, never by writing cookies.
