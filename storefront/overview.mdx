The storefront API serves the content a Fluid store shows its shoppers: products, the groupings that organize them, and the pages, posts, and media around them. You read it to render a storefront, and you write it to manage that content from your own tools.

## Current version

The current storefront version is **v2026-04**. Its paths start with `/api/v202604/`. Every storefront resource is available on it, and there is no newer storefront version.

Older Fluid APIs still serve some of the same resources — for example the unversioned company API's product, page, and media endpoints. Those endpoints remain available, but they don't receive new fields or behavior. Build new integrations on v2026-04.

## Resources

The storefront API has eight resources. They share one design, so once you know one you know most of the others.

| Resource | What it is | Public catalog |
| --- | --- | --- |
| Products | Items you sell, with variants and country pricing | [List](/api-reference/storefront/public-products-catalog) · [By slug](/api-reference/storefront/public-product-by-slug) |
| Categories | A nested tree that organizes products or other content | [List](/api-reference/storefront/public-categories-catalog) · [By slug](/api-reference/storefront/public-category-by-slug) |
| Collections | Flat, hand-picked groups of products | [List](/api-reference/storefront/public-collections-catalog) · [By slug](/api-reference/storefront/public-collection-by-slug) |
| Pages | Standalone storefront pages built from a theme template | [List](/api-reference/storefront/public-pages-catalog) · [By slug](/api-reference/storefront/public-page-by-slug) |
| Posts | Blog posts | [List](/api-reference/storefront/public-posts-blog-catalog) · [By slug](/api-reference/storefront/public-post-by-slug) |
| Media | Videos, images, PDFs, and other files | [List](/api-reference/storefront/public-media-catalog) · [By slug](/api-reference/storefront/public-medium-by-slug) |
| Playlists | Curated sets of media | [List](/api-reference/storefront/list-playlists-public-storefront-catalog) · [By slug](/api-reference/storefront/show-a-playlist-public-by-slug) |
| Enrollment packs | Bundles a new member buys to join | [List](/api-reference/storefront/public-enrollment-packs-catalog) · [By slug](/api-reference/storefront/public-enrollment-pack-by-slug) |

See [Storefront resources](/storefront/resources) for what each one adds to the shared design.

## Two kinds of endpoint

Every resource has two sets of endpoints:

- **Public endpoints** — `/api/v202604/<resource>` and `/api/v202604/<resource>/<slug>`. No token. They serve what a shopper may see, and you call them on the store's own host.
- **Company endpoints** — `/api/v202604/company/<resource>` and `/api/v202604/company/<resource>/<id>`. A Bearer token is required. They serve and manage everything, including content that isn't live yet, and you call them on `https://api.fluid.app`.

See [Public and company endpoints](/storefront/public-and-company-endpoints) for how they differ.

## What every resource shares

- **The same response fields.** Every resource returns `id`, `slug`, `title`, `description`, `image_url`, `canonical_url`, `images`, `active`, `status`, `publish_at`, `seo`, `metafields`, and `languages`, then adds its own.
- **The same visibility model.** Lists show only live content. Looking up a slug directly can return content that isn't live yet. See [Visibility, drafts, and scheduling](/storefront/visibility).
- **The same list controls.** Search with `q`, filter with `filter[...]`, sort with `sort`, and page with `page[cursor]` and `page[limit]`.
- **The same translation model.** See [Translate storefront resources](/storefront/translations).
- **The same SEO model.** See [SEO for storefront resources](/storefront/seo).

<Warning>
  Metafields are returned in full on the public endpoints. Never store private or internal data in a storefront resource's metafields. See [Metafields](/storefront/metafields).
</Warning>
