Use the Member API to manage a member's own Sites. Use bundle uploads to publish a Site's build. Start with [Sites](/sites/overview) for the app, SDK and CLI workflow. To call the Member API from a Site's own pages, see [Call the Member API from a Site](/sites/member-api).

Use **Show a site** to read site details. When `share_url` is present, open it in a browser to view the published app; the details API does not render its pages.

Pins and the home site control the member's account navigation. They do not showcase a site on a public profile.

The owner database inspection APIs are read-only management APIs. They are separate from the database calls your site makes as a visitor. Follow [Inspect your site's data](/sites/database#inspect-your-sites-data) for the owner workflow.

For database reads and writes inside your app, use [the Site database](/sites/database). Its tables and access rules come from `db/schema.json` and are published with the build.

## Search engine indexing

A member's Site is not indexed by search engines until its owner turns indexing on, and a company admin can override the owner. See [Show your Site in search engines](/help/mist/search-engines) for what a member sees, and [Control whether a member's Site is listed](/help/admin/member-sites#control-whether-a-members-site-is-listed) for admins.

- **The owner turns indexing on or off** by sending `indexable` to [Change a site](/api-reference/sites/change-a-site). Only the Site's owner can, with a Bearer token that can write. A Site's own pages can't. Every site the Member API returns carries an `indexing` object that says what the owner chose, whether the company has locked the setting, what applies now, and whether search engines can list the Site now. A change while the company has locked the setting is refused.
- **A company admin overrides it** with `PUT` to `/api/company/v2026-10/member-sites/{id}/indexing-override`, sending `indexable` as `true` to always allow or `false` to never allow, and removes the override with `DELETE` to the same path. Both need a signed-in admin whose role has **Update** on **Application Themes**. A company API token on its own can't use them. The Company API's site shows the override, who set it, and whether search engines can list the Site now.

An override never changes the owner's own choice, and clearing it gives that choice back. Neither setting makes a private, unpublished or taken-down Site indexable, and company Sites and branches aren't covered. The company override requests are listed with the other Company member sites operations in the API reference.

## V1 copying

<Note>
V1 bundle-copy support is rolling out and is not yet available in production. Use it after the rollout reaches your environment and V1 Sites is enabled for your company.
</Note>

Copy the source site's published V1 build into a separate draft. Once its files are ready, publish the prepared bundle using the bundle workflow above.

Ordinary copies carry the build's database schema, not the source database rows.
