Use the Member API to manage a member's own sites. Use bundle uploads to publish a static V1 site's build. Start with [Build a member site](/member-sites-v1/overview) for the app, SDK and CLI workflow.

## APIs for static V1 sites

| Task | Reference |
| --- | --- |
| Manage sites | [List](/api-reference/sites/list-the-members-sites), [add](/api-reference/sites/add-a-site), [read](/api-reference/sites/show-a-site), [change](/api-reference/sites/change-a-site) and [delete](/api-reference/sites/delete-a-site) |
| Publish a build | [Start a bundle upload](/api-reference/site-bundles/start-a-bundle-upload) and [publish the bundle](/api-reference/site-bundles/publish-a-bundle) |
| Find published builds | [List a site's bundles](/api-reference/site-bundles/list-a-sites-bundles) and [make an earlier bundle current](/api-reference/site-bundles/make-an-earlier-bundle-current-roll-back). Read the rollback restrictions in the reference before using it |
| Share access | [Search share targets](/api-reference/site-share-targets/search-the-share-targets), [list shares](/api-reference/site-shares/list-a-sites-shares), [share](/api-reference/site-shares/share-a-site), [change permission](/api-reference/site-shares/change-a-shares-permission) and [stop sharing](/api-reference/site-shares/stop-sharing-with-an-audience) |
| Set account preferences | [Pin a site](/api-reference/site-pins/pin-a-site-to-the-members-menu), [order pins](/api-reference/site-pins/order-the-members-pins), [unpin](/api-reference/site-pins/unpin-a-site), [choose a home site](/api-reference/site-home/choose-the-members-home-site) and [clear it](/api-reference/site-home/clear-the-members-home-site) |
| Inspect the owner's database | [List tables](/api-reference/site-data/list-the-tables-of-a-sites-database) and [read rows](/api-reference/site-data/read-the-rows-of-a-table-of-a-sites-database) with the site owner's Bearer token |
| Download the database | [Download a site's database](/api-reference/site-database/download-a-sites-database) |

Pins and the home site control the member's account navigation. They do not showcase a site on a public profile.

The owner database inspection APIs are read-only management APIs. They are separate from the database calls your site makes as a visitor.

For database reads and writes inside your app, use [the member site database SDK](/member-sites-v1/database). Its tables and access rules come from `db/schema.json` and are published with the build.

## Compatibility endpoints

The **Member Sites compatibility** section keeps references for older integrations separate from the V1 workflow. Their existing links still work.

- **Liquid copy, publishing and versions** and **Liquid files and pages** describe the older Liquid content workflow. Publish static builds with bundles instead of [Publish a site](/api-reference/sites/publish-a-site), [Git versions](/api-reference/sites/list-a-sites-versions) or [restore a Git version](/api-reference/sites/restore-a-site-to-a-version).
- [Copy a site](/api-reference/sites/copy-a-site) currently copies the older Liquid content, not a static V1 bundle. It does not create a working copy of a V1 build.
- **Older database backend** describes the older database status, setup, table, row and schema-statement operations. Those operations do not manage the V1 database declared in `db/schema.json`. The database download listed above does use the V1 database.
- **Account menu integration** contains [the member's account menu](/api-reference/site-menu/show-the-members-account-menu) and menu removals. The menu endpoint remains available for integrations that draw account navigation; publishing or sharing a V1 site does not require you to build that menu.

See [Publish a member site](/member-sites-v1/publishing) for the recommended CLI workflow, and [Share a site](/member-sites-v1/overview#share-a-site) for visibility, access and credited links.
