A **member** is a person in a Fluid company — a customer, a rep, or a type the company defines. Fluid has two sets of member endpoints, and which one you use depends on **who is calling**:

| You are building | Use | Credential |
| --- | --- | --- |
| An app or portal where a member manages their own profile, orders, and team | The **member API**, `/api/member/v2026-10/...` | The member's own JWT |
| A back-office integration that manages a company's members | **Member management**, in the People section of the API reference | A company token |
| A shopper account page in a checkout | The Checkout API's shopper endpoints | A shopper's token — see [Checkout](/api/choosing-a-cart-surface) |

## The member API

The member API acts as **one signed-in member**. It is called with **that member's own credential** — never an admin, partner, company, or droplet token — and everything it returns belongs to that member:

- **The credential identifies the member.** No path, query, or body parameter ever names a member, so a request can't ask about anyone else.
- **Every endpoint is scoped to the member.** A member reads and changes only their own record and profile, their own memberships, orders they placed or are credited with, and seats inside their own team. An id outside that scope returns `404`.
- **Company data goes through the company APIs.** An admin, partner, or droplet integration uses the endpoints under [Member management](#member-management) and the rest of the API reference, not these.

In the API reference, every member endpoint is in the **Members** section.

### Credentials

Send the member's credential as a Bearer token to `https://api.fluid.app`:

```bash
curl "https://api.fluid.app/api/member/v2026-10/me" \
  -H "Authorization: Bearer <the member's JWT>"
```

A member credential is a member session JWT, a portal JWT whose login is linked to a membership in that company, or a member token.

The identity, profile, and order endpoints refuse, with `401`:

- Company, partner, public (`pub-`), and droplet installation tokens.
- Admin credentials, including impersonation, and any credential for a member whose user is also an admin of that company.
- A credential for a member who is removed, inactive, or locked, or whose company is inactive.

A JWT that can also travel in a URL is **read-only** on these endpoints: a write with it returns `403`.

### Team

A member can read their own team — the part of their company's genealogy below them — and request moves within it:

| Operation | What it does |
| --- | --- |
| [Show a seat](/api-reference/team/show-a-seat-in-your-team) and [its recorded placements](/api-reference/team/list-a-seats-recorded-placements) | One seat in the member's team |
| [Children](/api-reference/team/list-a-seats-children), [descendants](/api-reference/team/list-a-seats-descendants), [subtree](/api-reference/team/list-a-seats-subtree), and [one level](/api-reference/team/list-one-level-below-a-seat) | Walk the team, one cursor page at a time |
| [Count seats by level](/api-reference/team/count-seats-by-level-below-a-seat) | Team size at each level below a seat |
| [Preview](/api-reference/team-moves/preview-a-move-in-your-downline) and [request](/api-reference/team-moves/move-a-seat-in-your-downline) a move | Check a move in the member's downline, then submit it |
| [List](/api-reference/team-moves/list-your-move-requests), [show](/api-reference/team-moves/show-one-of-your-move-requests), and [withdraw](/api-reference/team-moves/withdraw-one-of-your-move-requests) move requests, and [show a move job](/api-reference/team-moves/show-one-of-your-move-jobs) | Track the member's own requests |

- **Team reads are limited to the member's current team.** A member never sees seats outside it, and the member's own seat can't be moved.
- **Moves take effect on the server's clock.** An immediate move returns `200`. A move that needs approval, or runs later as a job, returns `202` with a receipt you can follow.
- **A company has to enable moves.** Until it does, move requests are refused.

<Warning>
  The team endpoints check credentials differently from the identity, profile, and order endpoints. They refuse company, partner, public, and droplet tokens with `401`, but they also accept an admin's own user token or portal JWT — acting only as that admin's own membership and team — and they allow moves with a session or portal JWT. Integrations should still call them with the member's own credential.
</Warning>

## Member management

These endpoints are in the **People** section of the API reference, under **Members**.

A company manages its members with a company token that has the `members` permission:

| Operation | What it does |
| --- | --- |
| [List members](/api-reference/members/list-members) and [find a member](/api-reference/members/find-a-member-by-a-unique-identifier) | Search the company's members |
| [Create](/api-reference/members/create-a-member), [get](/api-reference/members/get-a-member), and [update](/api-reference/members/update-a-member) a member | Manage one member |
| [Change a member's type](/api-reference/members/change-a-members-type) | Move a member between customer, rep, and your own types |
| [Get a member's sponsor genealogy](/api-reference/members/get-a-members-sponsor-genealogy) | A member's sponsor line. A rep can also call this for their own downline. |

Use these endpoints rather than the older customer and member endpoints listed with them when the member's type matters: only member management returns `member_type`.

To manage the company's genealogy trees themselves — defining trees, placing members, and approving moves — use the **Genealogy** endpoints in the **People** section of the API reference, with a company token.
