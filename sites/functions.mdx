A function is a small piece of server code that belongs to your site: a form handler, an API route, a webhook receiver or a scheduled job. Each one is a file in the site's `functions/` folder.

## Write one

```ts functions/rsvp.ts
export default async (request: Request, ctx) => {
  const { eventId } = await request.json();
  await ctx.fluid.db.from("rsvps").insert({ event_id: eventId });
  return Response.json({ ok: true });
};
```

A handler takes a web-standard `Request` and returns a `Response`. `ctx` carries the caller, the site's [secrets](/sites/env-vars), `ctx.fluid.db` for the site's database and `ctx.fluid.api` for the Fluid API.

Declare each function in `config/functions.json`:

```json config/functions.json
{
  "version": 1,
  "functions": {
    "rsvp": { "access": "signed_in" },
    "nightly-digest": { "access": "key", "schedule": "0 6 * * *" }
  }
}
```

| `access` | Who can call it |
| --- | --- |
| `public` | Anyone |
| `signed_in` | A signed-in visitor |
| `key` | A caller with one of the site's API keys, such as another service's webhook |

`schedule` is a five-field cron in UTC, at most once a minute.

## Call one from the page

```ts
const res = await fluid.fn.fetch("rsvp", {
  method: "POST",
  body: JSON.stringify({ eventId: "fall-gala" }),
});
```

The function runs at `/_fluid/fn/rsvp` on the site's own address, as the visitor. `fluid deploy` builds and publishes functions with the rest of the site.

## When you need more

Functions suit short handlers. A project that needs server rendering, long jobs or its own Postgres is a [Mist app](/sites/site-or-app).
