Three commands take you from an empty folder to a public site.

## Before you start

- Node.js 24 or later.
- Git, which `fluid deploy` uses to save the site's source.
- A Fluid login for a company that has sites turned on. If publishing answers `404`, [contact support](/help/getting-help) to turn them on.

## Steps

<Steps>
  <Step title="Create the project">
    ```bash
    npm create @fluid-app/fluid-site my-event
    cd my-event
    ```

    This makes a Vite and React project with `@fluid-app/sites` already imported. `npx @fluid-app/create-fluid-site my-event` does the same. For a single HTML page and no build step, use the `html` template:

    ```bash
    npm create @fluid-app/fluid-site page -- --template html
    ```
  </Step>
  <Step title="Log in">
    ```bash
    fluid login
    ```

    If you don't have the Fluid CLI yet, install it first:

    ```bash
    npm install -g @fluid-app/fluid-cli @fluid-app/fluid-cli-member-site
    ```
  </Step>
  <Step title="Deploy">
    ```bash
    fluid deploy
    ```

    `fluid deploy` finds the framework, runs its build, creates the site the first time, publishes the build and prints the site's address, such as `https://yoli.com/sites/my-event`.

    The first deploy asks whether to make the site public. Pass `--public` to skip the question. Without a terminal to ask on, the site stays private until you run `fluid sites visibility public`.

    Before it publishes, `fluid deploy` commits the folder and pushes it to the site's source repository, so `fluid sites pull` can clone it later. Pass `--no-source` to publish without saving the source.
  </Step>
</Steps>

Run `fluid deploy` again after each change. Files Fluid already holds aren't uploaded again.

## Already have a project?

Skip the first step. Run `fluid deploy` in the folder of any Vite, Astro, plain HTML or Next.js static export project. It builds the project with the package manager its lockfile names. See the [framework guides](/sites/frameworks/vite) for what each one needs.

A Next.js app that needs a server isn't deployed: `fluid deploy` explains why and creates nothing. See [Site or App?](/sites/site-or-app).

## Deploy from CI

In CI, set `FLUID_TOKEN` to an admin or member API token instead of running `fluid login`. The CLI reads it before any saved login.

```yaml .github/workflows/deploy.yml
- run: npm install -g @fluid-app/fluid-cli @fluid-app/fluid-cli-member-site
- run: fluid deploy --public
  env:
    FLUID_TOKEN: ${{ secrets.FLUID_TOKEN }}
```
