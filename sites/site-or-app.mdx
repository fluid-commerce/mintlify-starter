Fluid hosts two kinds of project. Most projects should be a **site**. Pick an **app** only when the project needs something a site can't do.

## The rule

Make it a site, unless it needs one of these:

| The project needs | Make it | Why |
| --- | --- | --- |
| Its own domain, such as `events.yoli.com` | App | Sites live at your company's addresses and have no custom domain |
| Server rendering, such as a Next.js app with server components or API routes that render pages | App | A site serves the files your build wrote |
| Server code: long jobs, large dependencies, a Postgres database | App | A site serves files, and site [functions](/sites/functions) aren't available yet |

Everything else is a site: landing pages, event pages, calculators, forms, small dashboards, anything a static build with the site database can do.

## Side by side

| | Site | Mist app |
| --- | --- | --- |
| Code | Any static build: Vite, Astro, plain HTML, Next.js static export | Next.js, from Fluid's starter |
| Deploy | `fluid deploy` | Push to the app's repository |
| Database | `fluid.db`, tables in `db/schema.json` | Its own Postgres |
| Server code | None yet: [functions](/sites/functions) are coming | Full Next.js server |
| Address | Your company's storefront, at `/sites/<handle>` | Your own domain, or Fluid's |
| Read more | [Sites quickstart](/sites/quickstart) | [Mist apps](/mist-apps/overview) |

## Changing your mind

A public company site that outgrows these limits can be converted into an app, which starts from the site's code. See [Convert a site to an app](/sites/convert-to-app).

## Ask Fluid

[Recommend a site or an app for a new project](/api-reference/member-site-conversion/recommend-a-site-or-an-app-for-a-new-project) applies the same rule to a description of what you're building. It reads and changes nothing. `fluid deploy` asks it when it finds a Next.js app with a server, and prints the answer with the reasons.
