`fluid sites dev` runs your site on your machine with a database of its own. `fluid.db` works before you publish, and nothing you write locally reaches the live site.

```bash
fluid sites dev
```

It starts your project's `dev` script, or serves the build in `dist` when `package.json` has none, at `http://127.0.0.1:9500`. Hot reload keeps working.

## What's local and what isn't

| Part | Under `fluid sites dev` |
| --- | --- |
| `fluid.db` | Answered from `.fluid/dev.sqlite` in the folder, with the same table rules as the live site |
| `fluid.auth.me()` | You, as a stand-in owner `local-owner`, or a signed-out guest with `--viewer guest` |
| `fluid.api` | Not available yet: answers `503` |
| `fluid.cart` | Not available: there is no storefront around the page |
| `/_fluid/sdk/v1/sites.js` | Not served. Install `@fluid-app/sites` from npm for local work |

Rows you write locally carry `created_by` `local-owner`. The command adds `.fluid/` to `.gitignore`, and no publish ever uploads it.

## Options

```bash
fluid sites dev --port 3000       # another port
fluid sites dev --viewer guest    # browse as a signed-out visitor
fluid sites dev --reset-db        # start again from an empty database
fluid sites dev --dir build       # serve another build folder when there's no dev script
```

## Schema changes

Saving `db/schema.json` updates the local database at once. A change that drops or renames data waits for you to confirm it at the terminal. See [Change the schema](/member-sites-v1/database#change-the-schema).
