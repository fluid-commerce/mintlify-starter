A public Site can ask visitors for a password before it opens. Anyone who has the address and the password can open it, signed in or not. Use it to share a page with people outside your company's member list, such as event guests, without making the page open to everyone.

## Who is asked for the password

| Visitor | Asked for the password? |
| --- | --- |
| The Site's owner | No |
| Company admins | No |
| Members the Site is shared with, including shares that can edit | Yes |
| Every other member, and guests | Yes |

A password Site is public, so the people a share names don't get anything a stranger with the password doesn't. While a Site has a password:

- Shares that can edit open nothing. Only the owner, and company admins on a company Site, can read or change its drafts. Remove the password to give editors their access back.
- The Site leaves its share holders' list of Sites. They open it like any visitor, by its address and the password.

## What a visitor sees

In place of the Site, a visitor sees **This site is password protected**, a **Password** field and **Open site**. The page names nothing about the Site, and search engines are asked not to index it.

- **Each page load asks again.** The password opens the Site for that one page load. A reload, a new tab, or coming back to the page asks for it again, and an open page is asked again after 8 hours.
- **A wrong password** shows "That password isn't right. Try again." The answer is the same whether the password was wrong or the Site can't be opened at all, so it tells a visitor nothing about the Site.
- **Too many tries** shows "Too many tries. Wait a few minutes, then try again." One address can try 10 times in 5 minutes, 50 times an hour, and 5 times a minute on one Site. A Site that gets many wrong passwords in a short time slows down only the visitors who got it wrong.

Changing or removing the password ends every page that's open with the old one.

## Password rules

A Site password has at least 6 characters, at most 72 bytes, and at least one letter, one digit and one symbol. A symbol is any character that isn't a letter or a digit, a space included. Nothing is trimmed, and nothing else is required. Fluid never shows a password back, in the admin, Mist, the CLI or the API.

Only a public Site has a password. A branch never does: it's always private.

## Private Sites keep their password

Making a password Site private keeps its password. Making it public again asks visitors for that same password. Only removing the password takes it away.

The API shows this with two fields on every Site:

| Field | Means |
| --- | --- |
| `password_protected` | `true` while the Site is public and asks for a password |
| `password_updated_at` | When the password was last set, while the Site keeps one, whatever its visibility. `null` when it has none |

A protected Site's `visibility` is `public`. Read `password_updated_at` to know whether a Site has a password, and `password_protected` to know whether visitors are asked for it now. A private Site that kept its password reads `password_protected: false` with `password_updated_at` set. In a company's list of Sites, `filter[visibility]=public` returns protected Sites too.

## Set, change or remove the password

The Site's owner, or a company admin, sets the password, on company Sites and members' Sites alike.

<Note>
Site passwords need the Sites gateway, which isn't on for every company yet. Until it is, setting a password is refused with `password_unavailable`. Removing one always works.
</Note>

### With the API

As the Site's owner, [change the site](/api-reference/sites/change-a-site) through the Member API:

```bash
curl -X PATCH "https://api.fluid.app/api/member/v2026-10/sites/{id}" \
  -H "Authorization: Bearer $MEMBER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "password": "fall-2026!" }'
```

- `{ "password": "..." }` sets or changes the password. `{ "password": null }` removes it.
- `{ "visibility": "public", "password": "..." }` makes a private Site public behind the password in one change.

As a company admin, [change the member site](/api-reference/member-sites/change-a-member-site) through the company API, with `application_themes.update`:

```bash
curl -X PATCH "https://api.fluid.app/api/company/v2026-10/member-sites/{id}" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "member_site": { "password": "fall-2026!" } }'
```

A member's Site needs an admin signed in as themselves, not an API token.

## Errors

A refused password change answers `422`. `error.details.error` names the code, and `error.details.password` holds the message:

```json
{
  "status": 422,
  "error": {
    "message": "Password must include a symbol",
    "details": {
      "error": "password_needs_symbol",
      "password": ["Password must include a symbol"]
    }
  }
}
```

| Code | Means |
| --- | --- |
| `password_too_short` | Fewer than 6 characters |
| `password_too_long` | More than 72 bytes. A character outside plain letters, digits and symbols takes more than one byte |
| `password_needs_letter` | No letter |
| `password_needs_digit` | No digit |
| `password_needs_symbol` | No symbol |
| `password_requires_public` | The change would leave the Site private. Send `"visibility": "public"` with the password |
| `password_not_for_branch` | The Site is a branch, which is always private |
| `password_unavailable` | The Sites gateway isn't on for the company yet |

A Site a company admin [took down](/storefront/sites#when-a-site-is-taken-down) can't lose its password while it stays public, until an admin brings it back.
