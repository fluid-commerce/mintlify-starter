Each publish is a deployment. Fluid keeps a site's recent deployments, so you can make an earlier one live again instantly, with nothing to rebuild.

## Roll back

```bash
fluid sites rollback            # back to the previous deployment
fluid sites rollback <id>       # back to a particular one
```

The command asks before it changes the live site. Pass `--yes` to skip the question, for example in CI.

A deployment whose build has a `db/schema.json` can't be made live again yet, because restoring a site's database isn't available. That rollback is refused and nothing changes.

## List deployments

The site's deployments, newest first, each with when it was published, who published it, its size, its address and whether it's the live one, are on the site's deployments list in the API: `GET /api/member/v2026-10/sites/{site_id}/deployments` for a site you own, or `GET /api/company/v2026-10/member-sites/{id}/deployments` as an admin.

To roll back through the API, see [Make an earlier bundle current](/api-reference/site-bundles/make-an-earlier-bundle-current-roll-back).
