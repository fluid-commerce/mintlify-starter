<Note>
Logs and traffic need the sites gateway, which Fluid turns on for each company. Until then these commands answer `404`. To turn it on, [contact support](/help/getting-help).
</Note>

## Logs

```bash
fluid sites logs                                  # up to 100 lines from the last 7 days, oldest first
fluid sites logs --tail                           # keep printing new lines as they arrive
fluid sites logs --since 1h                       # lines from the last hour (or 15m, 2d)
fluid sites logs --since 2026-11-10T09:00:00Z     # lines since a time, in ISO 8601
fluid sites logs --limit 200                      # at most 200 lines, up to 500
fluid sites logs ./my-event                       # the site in another folder
fluid sites logs --site my-event                  # by handle or id, from any folder (Sites plugin 0.1.429+)
```

Each line has when it happened, its level, where it came from and a message. Lines come from:

- **`publish`**: each upload's start, its publish and who published it, an upload that failed or expired, and each rollback.
- **`build`**: each build Fluid ran for the site, what it printed and how it ended.
- **`function`**: one line for each call of the site's [server functions](/sites/functions), with the function, the caller (`page`, `public`, `key`, `schedule` or `agent`), the request id, the status and the time it took. A timeout or a `5xx` answer is an `error` line, and a refusal, such as the rate limit, a `warn` line. The rate limit writes one line a minute. What a function prints with `console`, and an error it throws, come just before the call's line. Only the site's owner, and admins whose role has **Update** on **Application Themes** and **View** on **Member Site Data**, see those printed lines. See [Logs and usage](/sites/functions#logs-and-usage).

A function line can arrive a second after a later line from another source. Lines from the site's host come later.

## Traffic

```bash
fluid sites traffic                  # the last 24 hours
fluid sites traffic --period 7d      # 24h, 7d or 30d
fluid sites traffic --json           # the report as one JSON object
```

It shows visits (pages opened), an estimate of unique visitors, the top pages, the top referring sites, and how many requests ended in an error, counted as `4xx` and `5xx`. For a site with server functions it also counts each function's calls, errors, timeouts and rate-limited calls, its wall time and the bytes it answered, by function and by caller. Fluid counts traffic as it serves the site, so a period from before counting started reads zero.
