A site is a web project that Fluid hosts for your company. It doesn't have to be about commerce: an event page, a podcast landing page, a calculator, or a small dashboard for your team all fit. If you'd otherwise put it on a static host, you can put it on Fluid instead.

A site is static files you build on your machine or in CI, plus three things Fluid gives every site:

| What | What it does | Read more |
| --- | --- | --- |
| The SDK | `@fluid-app/sites`: who is signed in, the Fluid API as the visitor, the storefront's cart | [The member sites SDK](/member-sites-v1/sdk) |
| A database | Tables declared in `db/schema.json`, read and written with `fluid.db` | [The member site database](/member-sites-v1/database) |
| Hosting | A public address, HTTPS, and every earlier version kept so you can roll back | [Deployments and rollback](/sites/deployments) |

## What a site can't do

- **No custom domain.** A site lives at your company's addresses. A project that needs its own domain is a [Mist app](/mist-apps/overview).
- **No server rendering.** Fluid serves the files your build wrote. Light server code runs as [functions](/sites/functions).

When a site outgrows these limits, [convert it to an app](/sites/convert-to-app).
