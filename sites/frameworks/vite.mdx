Vite projects work as they are. `npm create @fluid-app/fluid-site my-site` starts you on Vite and React; an existing Vite project needs only the SDK.

## Set up

```bash
npm install @fluid-app/sites
```

Import it once, at the top of your entry file:

```ts src/main.tsx
import { fluid } from "@fluid-app/sites";

const me = await fluid.auth.me();
```

Keep Vite's default `base` of `/` and its default build folder, `dist`.

## Routing

With no `config/routes.json`, every path that isn't a file is answered by `index.html`, which is what a client-side router needs. Inside the storefront, let your router follow Back and Forward:

```ts
fluid.history.onGo((path, hash) => router.navigate(path + (hash ?? "")));
```

See [Routes](/member-sites-v1/declarations#routes) to send some paths to other files.

## Search engines and link previews

A single-page app's `index.html` is empty until its script runs, so a crawler that doesn't run JavaScript sees nothing. Add the `fluidSite()` plugin from `@fluid-app/sites/vite`, and the build writes what crawlers read:

```ts vite.config.ts
import react from "@vitejs/plugin-react";
import { fluidSite } from "@fluid-app/sites/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [react(), fluidSite()],
});
```

After `vite build`, it reads `config/meta.json` and writes:

- the title, description, Open Graph and Twitter tags into `index.html`;
- one `index.html` per route, such as `events/index.html`, each with that route's own tags;
- `llms.txt`, and `sitemap.xml` when `config/meta.json` gives the site's absolute `url`.

A route marked `noindex` is left out of the sitemap and `llms.txt`. See [Page titles and previews](/member-sites-v1/declarations#page-titles-and-previews) for `config/meta.json`.

## Deploy

```bash
fluid deploy
```

Run [`fluid sites dev`](/sites/local-development) instead of `npm run dev` to get a working `fluid.db` while you build.
