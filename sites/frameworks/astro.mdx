An Astro project with static output, Astro's default, works as a site. A project that sets `output: "server"` needs a server, so it's a [Mist app](/sites/site-or-app).

## Set up

```bash
npm install @fluid-app/sites
```

Use the SDK in a client-side `<script>`, which Astro bundles for the browser:

```astro src/components/Hello.astro
<p id="hello">Hi there</p>
<script>
  import { fluid } from "@fluid-app/sites";
  const me = await fluid.auth.me();
  if (me.viewer) document.querySelector("#hello")!.textContent = `Hi, ${me.viewer.name}`;
</script>
```

## Pages and routing

Astro writes each page as a folder with an `index.html`, such as `about/index.html`. The site answers `/about` with `/about/index.html`, so links work with no configuration.

With no `config/routes.json`, a path that matches no page is answered by `/index.html`. To show your own `404.html` instead, add a `config/routes.json` that lists your routes. See [Routes](/sites/declarations#routes).

## Deploy

```bash
fluid deploy
```

Astro builds to `dist`, which is where `fluid deploy` looks.
