AI agents such as Claude, ChatGPT and Gemini read stores and shop on a person's behalf. Every live Fluid storefront answers them on its own host, with no app to install and no theme change. A merchant gets these from the start, and so does every store an agent [launches on Fluid](/api/agent-launch).

This page lists what a shopping agent can use on any Fluid store, and what isn't available yet. To build your own front end instead, see [Build a headless storefront](/storefront/headless-storefront), which doesn't include these features.

## Protocols Fluid supports

| Protocol | What it's for | On Fluid |
| --- | --- | --- |
| [Personal Agent Protocol (Poppy)](/concepts/poppy) | Tells a personal agent, such as Meta's Muse, who the company is and how to work with it. | Every store serves `/.well-known/poppy.json`, pointing to its UCP profile. Shopper sign-in and Poppy conversations aren't available yet. |
| [Universal Commerce Protocol (UCP)](/concepts/ucp) | Agent catalog, questions, carts, checkout and orders. | Every store serves catalog search and lookup, Ask, carts, checkout with Google Pay or a hosted-checkout handoff, and orders. |
| [Agent2Agent (A2A)](/concepts/a2a) | One agent discovering and messaging another. | Every store serves an Agent Card and a JSON-RPC endpoint whose agent answers questions about the store. |
| Agentic Commerce Protocol (ACP) | OpenAI's protocol for shopping in ChatGPT: a product feed and agent checkout. | The product feed only: a US store serves its catalog at `/feeds/openai-products.jsonl.gz`, for the merchant to add in ChatGPT. ACP checkout isn't supported; ChatGPT shoppers check out on the store. |
| Agent Payments Protocol (AP2) | Mandates that let an agent pay on a person's behalf. | Not supported. Agents pay through UCP with Google Pay, or hand the shopper to hosted checkout. |
| Model Context Protocol (MCP) | Tools for the merchant's own AI agents. | The Fluid MCP server and the docs MCP server run and document a store, not shop it. See [Connect AI tools](/guides/connect-ai-tools). |
| Web Bot Auth | A signature that proves which agent sent a request. | Used to identify the agent behind an order. See [See which orders an agent placed](#see-which-orders-an-agent-placed). |

## What every Fluid storefront serves

Replace `https://<store>` with the storefront's host, such as `https://<subdomain>.fluid.app` or the store's custom domain.

| Path | What an agent gets |
| --- | --- |
| `/llms.txt` | A generated [llms.txt](https://llmstxt.org/) for the store: what it sells, the countries, currencies and languages it serves, its collections, pages and policies, and links to its agent APIs. Served as `text/plain`. |
| `/agents.md` | The same document, served as `text/markdown`. |
| A product, collection, category, page or blog post URL plus `.md` | A markdown version of that page, with live prices. `/home/shop.md` lists every product. |
| A product, collection, category or page URL plus `.json` | The same data as JSON. |
| `/.well-known/poppy.json` | The store's [Personal Agent Protocol](/concepts/poppy) document, pointing personal agents to its UCP profile. |
| `/.well-known/ucp` | The store's [Universal Commerce Protocol](/concepts/ucp) discovery profile: the protocol versions it serves, its REST endpoint, and its capabilities. |
| `/api/ucp/{version}/...` | The UCP service: catalog search and lookup, Ask, carts, checkout and orders. |
| `/.well-known/agent-card.json` | The store agent's [A2A](/concepts/a2a) Agent Card. |
| `/api/a2a` | The store agent's A2A JSON-RPC endpoint. |
| `/feeds/openai-products.jsonl.gz` | The store's catalog as an OpenAI product feed, for US stores. |
| `/api/v202604/products` | The public [storefront catalog API](/storefront/overview), with `?q=` to search and `?country=` and `?lang=` to choose the market and language. No authentication. |

When the storefront is turned off, or the company's account is paused for billing, these paths answer the store's 404 page, like any other missing storefront URL.

<Tip>
  A merchant can replace the generated llms.txt. Publish an `llms_txt` template in the active theme, and the store serves that text in full instead. Keep its links to the store's agent APIs, or agents won't find them.
</Tip>

### Send shoppers to the HTML page

The `.md` and `.json` versions are for the agent to read. When the agent links a shopper to a product or page, it should use the HTML URL. Keep any member path in the URL, such as `https://<store>/<username>/products/<slug>`: that path is how [FairShare](/concepts/fair-share) credits the member who shared it.

## See which orders an agent placed

Fluid records when an AI shopping agent places an order, whether the agent used UCP or completed the hosted checkout in a browser. Recording never blocks or changes a checkout.

[List the company's orders](/api-reference/orders/list-the-companys-orders) returns an `agent` object on each order an agent placed, and `null` on a shopper's own order. Only a company admin gets the field. The order is checked after it's placed, so `agent` can stay `null` for a short time. Its `classification` says how Fluid knows:

- `verified`: the agent signed the checkout request with Web Bot Auth, and the signature checked out against the agent's published key.
- `declared`: the agent named itself, such as in a `UCP-Agent` header or its user agent, but no signature was verified.
- `inferred`: only circumstantial evidence, such as a headless browser.

Other order reads, such as a single order and order webhooks, don't include `agent` yet. On the Home dashboard, an agent's order isn't counted in any channel of **Channel economics**.

## Build the whole purchase yourself

An agent that needs more than UCP covers can use Fluid's own APIs:

- The [checkout API](/guides/build-shopping-cart) (`/api/checkout/v2026-04/...`) creates a cart, adds items, sets the address and shipping, and completes checkout. See [Build a headless checkout](/api/guides/headless-commerce) and [Choosing a cart surface](/api/choosing-a-cart-surface).
- The [storefront API](/storefront/overview) reads products, collections, pages and their translations, per country.

## For the merchant's own agent

The pages above are for agents that shop. An agent that builds or runs the store works through the authenticated APIs instead:

- [Agent signup](/api/agent-signup) and the [agent launch guide](/api/agent-launch) create and set up a company.
- [Connect AI tools](/guides/connect-ai-tools) adds the docs MCP server, the Fluid MCP server and the Fluid CLI to an agent.
- [Authentication](/api/authentication) explains tokens.
