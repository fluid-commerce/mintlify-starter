FairShare is Fluid's JavaScript SDK for direct sales. It works out which rep should get credit for a visit, carries that credit into the cart and the order, and adds cart, lead capture, and media widgets to the page. It runs on Fluid storefronts and on any other website you add it to.

## How FairShare works

FairShare runs in the browser. On every page load, and on every client-side navigation, it sends the page URL to Fluid. Fluid resolves the rep for that page, and FairShare uses the result for the cart, lead capture, and media on it.

### Installation

On a Fluid storefront, FairShare is already installed: Fluid loads it through a global embed when the company is created. Don't add it again. See [FairShare SDK and the storefront](/storefront/fairshare-sdk).

On any other website, add this tag to the `<head>`:

```html
<script
  defer
  type="module"
  id="fluid-cdn-script"
  src="https://assets.fluid.app/scripts/fluid-sdk/latest/web-widgets/index.js"
  data-fluid-shop="acme"
></script>
```

- `data-fluid-shop` is your company's Fluid subdomain — `acme` for `acme.fluid.app`.
- `type="module"` is required. The script is an ES module and fails to load without it.

See [Installation](/sdk/installation) for every option.

## How a rep is resolved

Fluid resolves a rep from the page URL, checking in this order:

1. A `username` or `referral` query parameter.
2. A rep's own subdomain.
3. The first segment of the path. On a Fluid storefront this is the credit segment — `/jordan-lee/products/beet-blend` credits `jordan-lee`, and `/home/...` credits no one. See [Supported paths](/themes/supported-paths).

If the URL names no rep, the page has no attribution. Read the result for the current page with `window.FairShareSDK.getAttribution()`.

### Overrides

Attributes on the script tag override the URL. Use one when a page should always credit the same rep, or when your own site already knows who the rep is:

| Attribute | Value |
| --- | --- |
| `data-username` | The rep's Fluid username |
| `data-fluid-rep-id` | The rep's numeric Fluid ID |
| `data-email` | The rep's email address |
| `data-external-id` | The rep's ID in your own system |

FairShare uses the first attribute present, in this order: `data-fluid-rep-id`, `data-email`, `data-username`, `data-external-id`. It doesn't check that the rep exists, so an unknown value doesn't fall through to the next attribute.

The browser remembers an override. Removing the attribute doesn't clear it for someone who has already visited — clear the site's data to test URL-based attribution again.

<Note>
  `data-share-guid` is the older name for `data-username`: Fluid matches its value against rep usernames. It is still accepted, and it takes precedence over every other override. Use `data-username` in new code.
</Note>

### From visit to order

- **The cart takes the attribution of the page where it's created** — the first add to cart. The order inherits it.
- **Adding more items doesn't change the rep.** A cart started on a page with no rep stays uncredited.
- **Lead capture** credits the rep attributed on the page where the form is submitted.
- **Video views** from the media widget are credited to the page's rep.

### Across domains

Browser storage doesn't cross domains. A custom domain, a `fluid.app` subdomain, and `checkout.fluid.app` each keep their own. The cart reaches checkout through its token in the checkout URL. Keep shoppers on one domain from their first page to checkout, and make sure the page they arrive on carries the rep in its URL.

<Note>
  FairShare also records a browser fingerprint with its analytics. Fluid doesn't use it to decide which rep gets credit.
</Note>

## What FairShare adds to the page

- **Cart widget** — a slide-out cart that lets shoppers add products and go to checkout. See [Cart API](/sdk/cart-api).
- **Lead capture widget** — a form that saves a visitor's contact details as a lead for the attributed rep.
- **Media widget** — plays Fluid-hosted videos, images, and playlists, with a call to action. See [Media](/sdk/media).
- **Real-time cart updates** — optional live cart syncing, so a cart changed in another tab or by the server updates without a page refresh. Turn it on with `data-realtime-enabled="true"`.

See [Components](/sdk/components) for every widget.
